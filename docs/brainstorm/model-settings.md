**已确认方向**（2026-10-08）：

- 会话包含已提交图片后，直接禁止切换到不支持图片输入的模型。按“一刀切”理解，判定覆盖该会话的全部已提交历史，不随上下文压缩或清除重新开放；纯文本模型可用于另建会话。
- 执行中禁止切模型，结束后才可切；不保存“下一轮待切模型”，前端禁选、后端在切换事务中拒绝。
- 图片能力验证按最新要求精简够用，不成为保存模型的前置条件；加载可用模型列表、自定义 headers 均保留。
  早期“初始化主动探测”的候选由 §九最新取舍替代。
- 删除模型配置 JSON 的版本字段、兼容解析与迁移设计，按当前 Provider 的强类型配置直接解析。是否一并取消全库 schema 版本/旧库迁移已向 human 确认，未确认前不扩大到现有存储契约。
- 精简是从目标设计中彻底删除机制，不是延期排入路线图；有直接价值且无未满足依赖的功能现在评估并做，不以“首版”或“以后再加”替代方向判断。除以上具体已定规则外，其余删减仍为建议，不视为整批获批。

## 一、审查结论

模型入库、网页管理、Provider 工厂属于同一项端到端变更；但模型不能直接照搬人设的全部规则。
人设始终有固定兜底 id 1，模型允许零条，且涉及凭据、协议配置与历史推理兼容。

## 二、候选与取舍（未批准）

### 用户行为

- 空库：默认为空；有条目时默认恰好一个，是可行候选。还需选择默认不可删（先换默认）与允许删最后一条回到空库两种规则。
- 已选条目被删除：自动改用默认（沿用人设体验），或明确失败要求重选。前者存在切换服务商和发送历史的副作用，不能以“同构”代替 human 决策。
- 无模型入站：拒收且不落盘，或接受并按既有失败终态收尾。单纯禁用前端发送不能定义内核、旧库待跑输入与以后 Channel 的行为。
- 创建首个模型与设默认是否同事务、原先无选择的会话何时获得选择，需要一起定义。

### 工厂与配置

- 工厂只负责协议配置解析/校验与创建 Provider；凭据存储和加解密独立于服务商字段。注册表消费者是设置页的 kind 列表与执行时建实例。
- 强类型候选：外层使用 `kind + 不透明 JSON 文本`；对应 kind 在 HTTP/磁盘边界解析为自己的当前强类型配置，内部通过窄接口使用它。
  与在 core 枚举所有服务商配置相比，前者保持依赖方向；必须明确解析后的所有者和生命周期，不能让裸 `Value` 穿过多层，也不能校验一次、创建时重新猜字段。
- 模型配置没有版本/升级分支；未知 kind 或不符合当前类型的字段明确拒绝，不猜旧格式、不做兼容解析。
  现有 SQLite schema 版本/迁移的去留范围待 human 明确，不能把模型配置决定当成已批准的全库重写。
- 实例建议：每个 run 一次创建并持有至收尾；不建立跨 run 配置修订与实例缓存机制。
- Web 表单候选：当前唯一 openai kind 使用专用强类型表单；或 kind 提供有限的字段描述（文本、数字、枚举、映射及条件显示），Web 通用渲染。
  前者实现直接但字段知识在 UI 有一份；后者需定义描述/值/错误如何对应，不能扩展成完整表单引擎。两者最终语义校验均归 Provider。
- `Stored` 编辑必须区分保留、替换与切换到 Env；不能把空字符串解释成“保留”。凭据写命令、存储形式、只读展示分别建模，GET 不返回明文或密文 key。
- 加密依赖归属、主密钥的唯一写者与文件生命周期未定；在 B2 列明算法/密文布局、nonce 生成、完整性失败与原子创建行为。当前不选依赖版本。

### 依赖与迁移

保持 store 不依赖 core/Provider；Provider 实现依赖 core 的工厂 port；Gateway 经 Kernel 管模型；二进制装配实现。
工厂注册可以沿现有 Module 的声明阶段贡献；能力登记与配置启用的关系须在 B2 明确，不能用 bool 或类别字符串分发核心流程。
不新增 crate 的必要性尚未出现；新增模块、公开类型/签名仍走 B2。

旧 TOML 模型路径按现有草案拒绝，不擅自做隐式导入；B2 需说明已有用户重新录入后的会话、默认与待跑输入。
退役前检查配置解析/校验的正确性、key 隐私、失败提示、模型事实可审计性；旧路径在新路径迁移完成后删除。

## 三、实体与写者（候选责任边界）

| 实体 | 唯一写者 / 消费者 |
|---|---|
| kind 工厂登记 | Module 声明，经 Assembly 汇总；Kernel 设置与 Engine 消费 |
| 模型条目与加密凭据 | Kernel 接收 Web 命令，Store 事务保存；工厂消费解析后的配置与解析好的凭据 |
| 默认模型 | Kernel 命令，经 Store 保证与条目状态一致；建会话/空选择处理消费 |
| 会话模型选择 | 创建、空闲时用户切换及已批准的删除处理，经 Store 写入；认领消费；无待切模型字段 |
| run 模型事实 | Store 认领事务写入，写后不变；执行与审计消费 |
| run Provider 与明文凭据 | 执行侧从认领结果创建并在本轮持有；本轮所有调用消费，取消/收尾后释放 |
| 主密钥文件 | 单一启动组件（落点待定）创建/读取；凭据加解密消费，Web 不直接访问 |

状态草图（问号表示待决策，非实现许可）：

```text
模型集合：空 ──添加首条+定默认?──> 有条目/有默认 ──删除最后一条?──> 空
模型条目：不存在 ──添加──> 有效 ──修改──> 有效 ──软删除──> 已删除
会话选择：未选择 ──首个默认/用户选择?──> 选择 M ──空闲时用户切换──> 选择 N
          选择 M ──M 被删──> 保留已删引用 ──认领策略?──> 默认或本轮失败
run：未认领 ──事务读定模型──> Executing ──既有执行/取消/失败──> 既有终态
主密钥：不存在 ──首次创建──> 可读 ──丢失/损坏──> 明确报错（已有密文时不得重建掩盖）
```

关键场景时序：

1. **编辑竞态**：认领事务读定 M 配置/凭据来源 → Web 把 M 改为 N 配置 → 本轮从已读定输入创建 Provider →
   重试、工具往返和插话仍用本轮实例 → 下一轮才读取修改。不得在两次模型调用之间重新查活动条目。
2. **空库/删除竞态**：入站 → 与删除/默认修改按事务顺序确定认领事实 → 无可用选择时按批准的拒收或失败路径完成 →
   Gateway 继续服务。若入站拒收，拒收判断与落盘边界也必须避免检查后删除的竞态；不能只在 Web 检查。

必须成立的不变量：默认引用不指向已删除条目；零模型状态可启动；选择与本轮事实分开；
一个 run 的协议配置和凭据只读定一次；明文 key 不入库/响应/日志；未知库版本与不变量破坏明确 Err；
业务上的模型不可用不得误走持久层错误导致 Gateway 退出；所有实际执行复用既有事件、落盘、终态和取消。

## 四、多模态与 Web 图片输入

现有 `ContentPart::Text | File(FileRef)` 为历史表示提供了基础，但不等于已有附件系统。
`FileRef.path` 不能直接成为浏览器上传的可信路径或受权下载地址；Provider 的 user wire 目前只有字符串，
`request::text_of` 拒绝全部 File。这些是既有纯文本契约，需在 B2 逐项迁移，不能静默忽略图片。

### 能力与字段

- 区分 Provider 协议实现能力与具体模型条目的输入能力：同一 openai kind 的不同模型不一定支持图片。
  用强类型输入模态集合描述用户可选的能力，避免一个 `multimodal: bool` 混合图片、音频、视频和输出语义。
- **已定**：模型初始化设置时探测能力，加载可用模型列表并支持自定义 headers。
  模型列表帮助选名字，能力探测面向用户选定的具体模型；两者使用同一套配置、凭据和 headers，不从名字猜能力。
- 探测作为设置请求的一次性网络操作完成，结果写入模型条目；Web 展示进度、成功或明确失败。
  不引入常驻探测、周期任务或额外运行器。修改地址/模型等使旧结果失效的字段时，何时重新探测由 B2 明定。
- **推荐候选，待确认**：探测返回“已知能力”或明确错误；成功才提交本次模型设置，网络/鉴权/无法确认能力时拒绝本次提交。
  不将普通错误记为“不支持”，不因此新增持久化的“未知模型”状态。可靠确认图片支持/不支持的方法须在 B2 说清。
  提供手动重探入口，改变影响能力的配置时同步重探，复用一次探测流程；持久结果表达上次成功验证的配置能力，不保证上游永远不变。
- 手动编辑与探测结果写回须经过同一保存规则。推荐含图会话仍选着该条目时，降为不支持图片的本次提交拒绝，
  旧配置保留并明确显示拒绝原因与本次探测结果；不新增会话不可用状态。上游后来改变导致实际调用失败，仍走既有失败路径。
- 模型表单/只读模型视图向 Web 提供可输入模态；是否需要能力来源字段见 §六，不预先引入。
  Provider 校验与上游拒绝仍是最终协议事实。能力随本轮模型配置读定；执行中禁止切模型。
- 此次以图片输入作为端到端消费者。图片数量、格式、单图/总字节与像素上限需列入各责任 crate 的 `limits.rs`，
  表单的图片细节参数（如服务商需要的 detail）由对应 Provider 解释，不升格为所有模型的统一旋钮。
  同一图片业务限额只保留一个来源，各消费侧引用；HTTP 外层请求限额含文本/协议开销，不等于图片字节限额，Store 不重复执行入站校验。

### Web 与入站边界

- 候选体验：选择图片，并支持粘贴、拖入；发送前预览、移除、显示上传状态；失败保留草稿可重试；消息历史展示缩略图并可查看。
- 明确图片单独发送是否允许；文本与图片的顺序由强类型片段保存，新建会话与已有会话使用相同消息契约。
- HTTP 候选为发送时携带图片字节，或预上传后使用受管理引用；均不接收任意本机 path。服务端根据实际内容确认格式、尺寸与大小，客户端 MIME/文件名不是事实来源。
- 上传与图片读回使用 Gateway 的现有鉴权；不得把本机文件系统变成下载接口，也不得把 token 拼进公开图片地址。
  Web 用已鉴权的图片读取方式呈现；正文图片与静态前端资源的缓存、权限边界分别定义。
- **已定**：会话包含已提交图片后，禁止切换到不支持图片输入的模型。只在本地草稿选入图片不算；
  判定依据整段已提交历史，不根据当前模型上下文动态放宽。前端禁选并说明原因，后端在切换事务中拒绝。
  错误文案为“此对话包含图片，请选择支持图片的模型，或新建对话使用纯文本模型”。
- 首次图片提交与模型切换必须共同维护这一规则：若切换先提交，图片消息按已选模型能力拒收；
  若图片先提交，切换纯文本模型被拒绝。不得留下已含图片却选着纯文本模型的会话。
- 编辑同一模型条目也不能绕过限制：该条目被含图会话选着时，将输入能力降为不支持图片的修改应拒绝。
  B2 细化对应事务与错误；删除后的重新选择同样受含图限制，不自动回落。
- 执行中插图按当前 run 的能力判断；当前 run 不支持图片时拒收整条含图输入，保留 Web 草稿。
  不存在执行中的“下一轮模型选择”；条目配置编辑可能改变其后续能力，入站仍须维护本轮与会话含图约束。

### 附件所有权与依赖（未定）

候选 A：图片字节存 SQLite，引用与消息可同事务提交；候选 B：数据目录中不可变文件，库保存受管理 id 与完整元数据，
需要定义文件写入与消息提交之间的失败清理。二者均需定义未发送上传的生命周期和历史图片备份，不能先选路径再倒推所有权。

存储 A/B 尚未选定，文件方案并未排除。无论保存在哪里，模型请求都需读取和编码当前上下文中的图片，
要在读取字节前按元数据检查合计上限，并计入请求编码/组装的内存成本，超限明确失败；文件存储不自动消除该成本。
Store 已有 `context_window` 只返回最后 Boundary 后的上下文；不是每轮读取全部历史图片。
推荐压缩/清除只改变模型上下文，不删除图片原件：Web 历史继续可读；含图切换限制仍查全部已提交历史，两者有不同消费者。
图片自动过期/压缩后物理清理没有当前需求，不附带新增该机制。

一处资源解析负责按受管理引用读取图片，协议实现只决定 wire 映射；由谁持有字节、是否扩展 FileRef、
工具产出的本地文件如何进入同一资源边界，以及资源读取 port 放哪，都是 B1 待决策。
core 不依赖 Gateway；Provider 不借用 Gateway 的上传状态；store 不依赖 Provider。图片仍经既有输入/认领/执行/落盘/取消路径。

增加的实体、状态与时序：

| 实体 | 写者 / 消费者（候选） |
|---|---|
| 编辑器图片草稿 | Web 写；发送与预览消费 |
| 受管理图片与元数据 | 附件边界唯一写者（落点待定）；历史展示与模型输入读取消费 |
| 消息中的图片引用 | 入站提交经 Store 写；回放与本轮上下文消费 |
| 模型输入能力 | 模型条目设置写；Web、配置校验与本轮请求映射消费 |

推荐的发送时提交状态与关键时序见 §五 B；预上传不再作为另一个流程铺设实体状态与接口。
已提交图片须不可变、备份恢复后同一引用可读，缺失/损坏明确失败。

不变量：不能引用未完成或无权访问的资源；已提交消息引用的内容不会随原文件改变；重启/回放可读取同一图片；
消息落盘后失败仍可审计；图片不会绕过模型选择发到其它服务商；取消与失败不得留下半提交消息；
所有图片在 Web 和 Provider 两端消费同一份受管理资源事实。

## 五、方向收敛建议（待 human 批准）

当前 B1 的目标清楚，问题是把所有未知项平铺，且图片流程提前偏向了预上传。
建议先定用户行为与资源所有权，再写工厂签名；按以下三组收敛。只有明确标“已定”的方向获得确认，其余仍为建议。

### A. 用户行为与副作用

| 项 | 推荐候选 | 依据 / 尚需明确 |
|---|---|---|
| 默认 | 零条时为空；首条模型创建与设默认同事务；有条目时恰好一个默认 | 修正与空库启动的冲突。默认改变只影响新会话与尚无选择的会话，不批量改已有明确选择 |
| 删除 | 多条时先换默认再删默认；最后一条允许删除并清空默认；会话的已删选择保留，下一次执行明确要求重选 | 保留空库状态；不自动把历史发送到另一服务商。已认领的 run 用本轮实例继续 |
| 无模型输入 | 无可执行模型且没有可继续的当前 run 时，新输入拒收且不落盘；已落盘待跑输入由既有失败路径收尾 | 同一事务确定消费轮次/选择与入站副作用；不能把业务不可用升级为进程退出。`-p` 在新建会话/写输入前报错 |
| 图片能力（已定） | 初始化设置模型时探测，结果保存至条目 | 当前具体模型与协议共同决定；网络/账户错误不得误记为“不支持图片”；失败与重探契约在 B2 明写 |
| 模型列表 / headers（已定） | 加载可用模型列表，允许填写自定义 headers | 直接辅助模型配置与连接；本次实现，不延期；headers 的鉴权冲突与隐私边界必须明定 |
| 图片体验 | 选取/粘贴/拖入、预览移除，支持只有图片的消息 | 草稿保留直到发送成功；大小/数量/格式具体值在 B2 定 |
| 图片与切换（已定） | 会话已有已提交图片，禁止切换到不支持图片输入的模型 | 按会话全部历史判断；纯文本模型用于新会话。首次插图/切换及编辑能力不得绕过规则；执行中插图仍按当前 run 能力判断 |
| 执行中切换（已定） | 当前 run 未结束时拒绝切模型 | 无待切状态；前端禁选，服务端原子判断；不改变本轮配置快照 |

### B. 责任与存储

- 模型条目、凭据、模型实例、输入能力和图片资源分别表达独立语义。模型条目不拥有附件生命周期，附件不绑定产生它时选着的模型。
- **推荐图片字节存 SQLite，发送时与消息同事务提交**：Web 选图只产生本地草稿；一次发送携带文字与图片；
  Gateway 完整解析/校验后交 Kernel，由 Store 保存图片与消息，再发布既有 MessageAppended 并唤醒执行。
  收图/校验失败不写消息；事务失败不留下已提交附件；发送失败保留本地草稿；历史读图仍需鉴权。
- 这一候选省去预上传 id、未引用资源表与周期清理的消费者/生产者。复杂度留在有限请求体校验、
  图片/消息事务和鉴权读取，而不是藏到后台清理。代价是库体积与备份体积增长、请求携带完整图片；
  B2 必须定总字节/像素限额，原始字节按 blob 保存，不以 base64 字符串存库。
- Store 管持久化图片与凭据；Gateway 管 HTTP 字节边界；core 管历史选择与本轮模型输入；Provider 管协议映射。
  主密钥初始化与加解密建议归 Store 的凭据职责，装配侧提供启动必需的路径信息，不让 Provider 接触密钥文件。
- 凭据候选收敛为显式无鉴权、Stored、Env；实际是否发 Bearer 由 Provider 的强类型配置决定。
  自定义 headers 已确定保留；与 Provider 鉴权头的冲突规则在 B2 定义，不能隐式覆盖或忽略。
  建议自定义头值一并加密，避免靠头名猜哪些值敏感；写入/展示语义与 API key 一起细化。
  编辑粒度推荐按单个 header：未改的保留、改一个只替换一个、删除显式表达；展示头名与已设置状态，不通过空值猜“保留”。具体写类型由 B2 定义。
- 本轮 Provider 只创建一次，不做跨 run 实例缓存；持久快照保存协议配置与凭据来源事实，
  明文只用于内存实例，审计无需复制明文。凭据历史保留、替换后旧密文的处置和主密钥丢失处理在 B2 明写。
  配置/Env 变量名在认领事务读定，Env 实际值在本轮实例创建时只读取一次；不能把 SQLite 事务宣称为环境变量的原子快照。
- 推荐按协议实现专用强类型表单；字段语义和校验归 Provider。
  推荐彻底删除通用字段描述协议和通用渲染引擎，不预留另一套表单路径。

发送时提交候选状态/时序：

```text
Web 草稿：文字/图片选入 ──发送──> 正在提交 ──成功──> 清空草稿/显示历史
                                     └─失败──> 保留草稿/可重试
库资源：不存在 ──图片+消息事务提交──> 已被历史引用/不可变
run：认领读定模型 ──组装含图片字节的输入──> Provider wire ──既有执行与收尾
```

关键竞态：当前 A（纯文本）执行 → 切到 B（图片）的请求被拒绝 → 粘贴图片发送也按当前 A 拒收 →
草稿保留 → A 结束 → 用户切 B 并发送。空闲切换与新 run 认领按事务顺序确定，不能在认领后改变本轮选择。
首次图片提交仍需保证会话所选条目支持图片；模型条目编辑与本轮实例的独立生命周期继续由快照守住。

### C. 本次公开契约变化的范围

图片字节进入 Provider 会碰到已观察到的“历史事实 / 模型输入 / 供应商 wire”职责分散（正交审查 B）。
推荐在本次联合 B2 中一并定义窄的强类型模型输入：core 完成历史呈现与图片读取，Provider 只映射协议，
迁移现有 ModelRequest/ModelView 消费路径。这个建议是既有架构方向调整，须 human 单独认可，不能视作加图片的自然授权。
保持现有文本头、顺序、工具往返与失败呈现的等价证据；不合并工具参数 F、会话身份 E 等其它余项。

推理兼容建议由 Provider 声明并解释来源身份，core/历史只保存来源事实；本阶段至少区分 endpoint、
协议方言与请求模型，显示名/条目 id 都不足以代表它。具体哪些参数改变兼容性、旧历史身份未知时如何处理，
必须由 Provider 契约说明，不使用一份通用配置 hash 替代领域规则。

### B2 编写与实现顺序

同一用户功能跨多个 crate，写一份联合 B2，按变化轴分节；不把各模块的局部批准拼成隐式整体批准。

1. **先定行为表**：空库、默认、删除、无模型入站、执行中编辑/切换/插图、坏凭据与旧库待跑输入。
2. **再定所有权与类型**：工厂注册、当前 kind 配置解析、凭据写入/只读视图、能力探测结果、本轮快照、受管理图片与模型输入。
3. **再定签名与持久化**：Store/Kernel/Provider port 的方法、错误及副作用；当前库结构与事务边界；明确真正上游调用发生前失败如何审计，不伪造 model_call。
4. **最后定 HTTP 与 UI**：模型 CRUD/默认/会话选择、列表加载、初始化探测与 headers、同次提交图片、鉴权图片读取；前端字段、解码、选择器与草稿。
5. **逐调用方兼容审查**：装配与 CLI、Module/Registry、Store 的会话/认领/回放/列表摘要（纯图片预览）、Kernel 入站/设置、Engine/Scheduler、OpenAI Provider、Gateway、Web 与历史磁盘 payload。
   未知 kind、当前类型解析失败和库不变量明确报错；环境凭据失效/上游拒绝按本轮失败。不要把所有“模型错误”揉成一个错误出口。
6. **批准后分步实现**：存储/凭据 → 工厂与本轮实例 → 模型设置/列表/初始化探测 API/UI → 图片提交/回放/协议映射。
   改契约采用 parallel change，在迁移完成后删旧路径；中间步骤可编译，不构造明知失败的提交。

验收矩阵至少覆盖：空库 Web 可用且输入行为明确；首条/最后一条；运行中改 key/endpoint 不改变本轮；
删除所选模型不自动外发；执行中切模型拒绝且不留下待切选择；文字/纯图片/混合图片重启回放；
发送失败无半提交附件；受鉴权读图；含图会话切换纯文本模型被拒绝、修改模型能力不能绕过；
首次图片提交/切换竞态；旧配置/旧库/旧推理身份；秘密不出现在 DB 明文、响应与日志。

## 六、彻底删除与保留的重审（除已定项外待 human 批准）

上一轮把“删机制”“缩功能”“延期”混在一起，方向不准确；本节替代原精简清单。
推荐删除的机制从目标设计、路线图和预留接口一起移除，不另建恢复任务。

### 推荐彻底删除的机制

| 项 | 判定 / 分类 | 永久采用的替代规则；复杂度去向 |
|---|---|---|
| 执行中切模型（已定） | accept / 本次草案 | 执行中直接拒绝，结束后再切；无待切模型字段/事件。保留本轮快照及条目编辑边界 |
| 通用表单引擎 | accept / 本次草案 | 表单按协议实现；不提供字段描述协议、通用渲染器或两套表单。Provider 保持最终解析/校验，UI 直接实现本产品需要的字段 |
| 预上传资源池 | accept / 本次草案 | 图片随消息一次提交并同事务保存；不设上传 id、未引用资源状态和清理任务。成本转到有限请求/内存及库体积；资源保存方式待 human 批准 |
| 跨 run 实例缓存 | accept / 本次草案 | 每轮创建并持有实例；不设缓存键、淘汰和失效机制。承担每轮初始化客户端成本 |
| 凭据修订库 | accept / 本次草案 | 只保存当前密文，本轮已读定值留内存，run 保存非秘密事实。现有恢复将原 run 收尾为 Interrupted，无旧秘密重放消费者；不承诺恢复原凭据重执行 |
| 配置版本与兼容迁移（已定） | accept / 本次草案 | 删除模型配置版本、兼容解析、升级注册表与历史格式迁移；当前类型解析失败直接报错。全库 schema/旧库迁移是否一起取消待 human 明确 |
| 通用资源/兼容框架 | accept（砍框架）/ 本次草案及既有架构 | 不建所有文件统一资源平台、推理兼容插件/矩阵；受管理图片与 Provider 来源判断直接实现，各自有当前消费者 |

### 应保留并在本次判断实现的功能

| 项 | 重审结论 / 分类 | 当前直接价值与要求 |
|---|---|---|
| 拉取可用模型列表（已定） | reject（删除建议）/ 本次草案 | 本次保留并实现，辅助选择模型名；只接收服务商真实返回信息，不把列表等同于图片能力保证。HTTP/凭据/失败契约进入 B2 |
| 初始化能力探测（已定） | reject（删除建议）/ 本次草案 | 设置模型时一次探测并保存结果，复用 Provider HTTP 配置；不扩成后台探测体系。失败状态、请求范围、结果语义及失效字段进入 B2 |
| 输入模态强类型 | reject（不能因“通用”删掉真实能力）/ 本次草案 | Web 插图和模型切换有直接消费者；文本/图片的契约现在定义，不附带没有当前目标的音视频占位，也不把图片支持与输出能力混合 |
| 模型输入职责归位（正交 B） | needs-investigation（方向待 human）/ 既有架构 | 已有重复呈现与 Provider 理解历史的真实摩擦。应按实际消除耦合的收益选择必要重构，一旦选定方向就在本次做；不以“加图片先绕过去、重构往后放”减小文件数 |
| 自定义 headers（已定） | reject（删除建议）/ 既有公开契约 | 本次保留并在设置页管理；列表加载、能力探测与正式调用使用同一份 headers。完成强类型头校验、鉴权冲突及加密/脱敏，不把必要隐私边界称为过度设计 |

本轮快照、图片/消息事务、含图会话选择约束、API key 加密/脱敏、鉴权读图不属于可删机制。
未获批准的候选仍需收敛，但不再使用“首版不做、以后恢复”的含糊状态；淘汰方案只保留取舍结论。

## 九、能力验证按实际用途精简（最新取舍）

human 补充：当前实际使用 DeepSeek，所用 Flash 有多模态；能力验证只是小兜底，精简够用。
不继续联网调研；所用服务的外部契约需要核实时由 human 提供资料。

B2 据此采用轻量提案：表单显式选择“纯文本 / 支持图片”，保存两态 ImageSupport；
已有模型列表若带明确能力字段，只给可选建议。没有字段不妨碍手填和保存，

图片选择、运行中禁止切换、本轮快照、key/headers 加密及图片同事务提交继续是核心契约。
