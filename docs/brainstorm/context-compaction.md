# B1：上下文压缩与 `/compact`、`/clear`

**状态：B1 已收敛（2026-10-12）；[B2 已批准并实现、CLOSED](../blueprints/archive/context-compaction.md)。基本链路与构建检查通过，human 接手真实使用验收；OpenAI API key 实测因凭据 401 待补。**

前作：micbot [BP-043](../../../micbot/docs/blueprints/bp-043-context-compaction.md)（触发、锚点、累计 summary）、[BP-047](../../../micbot/docs/blueprints/bp-047-compaction-request-shaping.md)（请求形状：原样历史 + 末尾 user 祈使，实测真总结而不续写）、[BP-056](../../../micbot/docs/blueprints/bp-056-slash-commands.md)（`/compact` 手动入口）、[context-engineering](../../../micbot/docs/brainstorm/context-engineering.md) §六/§十四（改前缀是稀有昂贵事件）。本仓既有：[next-gen-architecture](next-gen-architecture.md) §4.9（Boundary 进 messages 表，不新增 summary 消息类型）、[mic-store](../blueprints/archive/mic-store.md)（`context_window` 只读最后 Boundary 之后；`core_model_calls.run_id` 为空表示压缩调用）。

## 一、需求

1. 压缩是一个**原子操作**，自动触发与 `/compact` 共用。
2. 自动：**发请求前**判断，「本模型上下文窗口 × 百分比」触发；窗口逐模型在模型设置页配，**不填默认 100k**；百分比是设置页旋钮。
3. 用当前会话的模型总结。
4. 压缩后保留 summary + 最近 N 个 **step** 原文，N 是旋钮。
5. `/compact <文字>`：文字可能是侧重说明，也可能就是下一个问题；压缩时带给总结，压缩完直接作为下一条输入执行。不区分两者。
6. 必读文件：模型在总结里列出与当前任务强相关的文件，压缩后自动读入。
7. 照顾 prompt 缓存。
8. `/clear`：清空模型上下文。
9. 入口：微信直接发文本；Web 需要命令交互与补全。
10. Web 展示压缩结果与成败；用户可撤回当前生效的压缩，将该边界置为失效，保留记录。

## 二、现状

- 读路径就位：`Store::context_window` 取最后 Boundary 之后的消息 + summary；`request.rs` 把 summary 放进 system prompt 的 context 块。缺写入方。
- 已有 `MessageBody::HarnessNote`：框架写给模型、以 user 角色呈现的系统消息（轮次提醒在用）。
- 审计 C（[over-design-audit](over-design-audit-2026-10-12.md)）建议删的 `Boundary::{Compaction, UserClear}` 因本项有了消费者，**保留**；C 其余项不受影响。
- 两种上游格式的 `input_tokens` 都含缓存命中部分，即该次请求的完整提示长度。当前有效窗口的用量优先用上游事实，缺失时按中文字符、英文文本等保守估算；与「输入框上下文占用圆环」共用口径。
- 模型无上下文窗口配置；窗口是跨 kind 事实，不进 `config_json`。
- 无斜杠命令机制、无 todo/plan 工具。

## 三、已拍板

### 3.1 一个操作

`compact(session, extra: Option<String>)`：读当前有效历史（含上一条 summary，产出累计 summary）→ 发一次总结请求 → 成功则**原子**写 `Boundary::Compaction`；失败不改变上下文，记录失败调用并通知用户。新输入与历史分开：可作为 `extra` 带给总结，压缩成功后仍作为输入执行。

### 3.2 自动触发

- 位置：run 循环里每次 `call_model` 之前（此刻工具调用都已配对闭合），长任务中途也能压。
- 判据：当前有效历史的 token 用量 ≥ 窗口 × 百分比；窗口未配按 100k。百分比默认 80%，至少留 20% 余量给新输入、总结指令和后续处理。
- 用量优先取对应当前有效窗口的上游 `input_tokens`；其后增加的历史按保守规则估算，无上游用量时估算整个有效历史。压缩、clear 或撤回后按最新有效 Boundary 所定义的窗口计算，不沿用旧窗口用量。
- 自动与手动都是先压历史、再处理新输入；尚未回答的输入按 `/compact` 后文字的同一规则处理。历史过长时先裁剪历史，切点仍保持完整 step；不另做大文件专项策略。
- **失败即停止本次 run**：上下文已到阈值，继续发只会更糟。会话里落通知说明原因与怎么办。

### 3.3 请求形状（照顾缓存）

沿用正常请求的 system + tools + 当前有效历史，末尾追加一条**总结指令**（`HarnessNote` 形态，按 user 角色呈现）。指令内容 = 固定的分节总结要求（用户诉求、关键结论与决定、涉及文件、错误与修正、未完成事项、当前进度）+ 必读文件清单格式 + 补充信息（新输入或 `/compact` 的文字，若有）。新输入不归入被压缩的历史。

- 未裁剪历史时，总结请求沿用主对话前缀，争取缓存命中；过长裁剪时优先保证请求可发送。
- tools 保留、禁止调用（`tool_choice: none`，与审计 D2 同一实测）。
- 压缩完成后前缀整体失效一次，此后 system（含 summary）+ 保留 step 再次稳定。

### 3.4 总结输出规整

总结请求的产出只取需要的部分，在边界一次规整：

- 只取正文文本；推理内容丢弃。
- 工具调用**不执行、直接丢弃**，记 warn 日志；有正文照常使用。理由：`tool_choice: none` 下多数上游本就不会产出，偶发产出不影响总结本身，按失败处理只会让「失败即停止」误伤。
- 上游请求失败、正文为空、或上游标明输出不完整（长度上限、内容审核截断／拒答）→ 压缩失败，停止本次执行并通知用户；不额外分析正文猜测是否拒答。HTTP 成功与输出完整性分别沿用现有 Provider 结果判定。
- 必读文件清单：缺失 = 无必读文件；路径不存在或读不了的跳过，在快照里注明。

### 3.5 保留最近 N 个 step

- step = 一次模型调用产出的 `Reply` 及其全部工具结果；按 step 数而非用户轮数，单个长任务中途也能压掉早期 step。
- Boundary 是追加写入的，保留的原文在它之前：Boundary 携带 `keep_from: MessageId`，`context_window` 返回 `keep_from` 起的消息 + summary。切点只落在 step 起点，不切开工具调用与结果。
- 用户输入落在保留区间内的照常保留。
- 尚未回答的新输入不依赖保留 step 的切点；压缩后按原文正常执行。
- 永远只以最新有效 Boundary 定义窗口；重复压缩从当前有效历史选取保留 step，clear 后不恢复此前历史。撤回压缩时跳过失效边界，恢复此前的有效窗口。

### 3.6 必读文件

总结输出末尾按固定格式列出必读文件，在边界解析成路径列表（规整规则见 3.4）。**通过当前会话可用的 `read` 工具读一次，快照随 Boundary 存**，之后每次请求原样放入，前缀稳定；模型改了文件自会再读。工具调用沿用已有工具执行与权限路径，core 不另建直接读文件路径、不依赖 `mic-tool-fs`；未开放 read 或读取失败时在快照注明。文件数与总字节有上限（`limits.rs`），超出截断并注明。

### 3.7 `/compact` 走会话队列

`/compact` 在 Channel 边界解析成强类型命令（不作普通文本进模型，不被 `absorb` 并入正在跑的 run），排在已有输入之后：

- `/compact`：轮到时执行 `compact(None)`，不调模型回复，结束。
- `/compact <文字>`：解析为「文字输入 + 执行前压缩标记」，整体仍属于指令，不作为普通待并入输入。认领后先 `compact(文字)`（总结指令里带上这段文字），成功后按普通 run 回答它。是侧重说明，模型简单确认；是问题，直接回答。
- 认领与 `absorb` 都遵守指令顺序，不跨过指令并入后续输入；压缩成功后文字执行复用现有 run 主路径。

推翻 next-gen §4.9「压缩不进 FIFO」：排队天然串行、可停止、不与 run 并发。

### 3.8 设置项

- 上下文窗口：模型设置页，每模型一项，存 models 表独立列；空 = 100k，页面上显示默认值。
- 触发百分比、保留 step 数：设置页「对话」组，全局一份。

### 3.9 `/clear`

同会话只写一条空的 `UserClear` 边界，再给用户发一条通知「已清空上下文，之前的对话不再带给模型」。与 `/compact` 一样在边界解析为命令、走会话队列。边界对应 clear 指令在队列中的逻辑位置：只清掉它之前的上下文，它之后已落盘的排队输入仍正常执行，不能用稍后执行时追加 Boundary 的物理消息 id 把这些输入一起排除。B2 明确这一顺序在存储契约中的表达。

会话设置（模型、人设、工作目录）不变，历史仍可在 Web 查看；Web 的「新建会话」维持现状，不加 `/new`。

### 3.10 压缩结果与撤回

- Web 的压缩分隔条显示「✓ 已压缩」，可展开查看 summary、保留步数和文件快照，并提供「撤回」按钮；失败显示失败原因，已撤回显示「已撤回」。展示状态以落盘事实为准。
- 撤回将该压缩边界置为失效，不物理删除 Boundary、summary、文件快照或调用记录。模型调用本身的成功与用量事实不改写成失败；这里只取消压缩结果的生效状态。
- 只能撤回当前生效的压缩边界；`UserClear` 不可撤回。如果后面已有新的有效 Boundary，旧压缩不再提供撤回。
- 撤回走同一会话队列；轮到执行时，该目标仍须是当前生效的压缩边界。一个事务将边界置为失效并写撤回通知，随后 `context_window` 读取最新有效 Boundary；没有有效边界则读取全部历史。
- 撤回恢复上一有效边界对应的 summary、文件快照及历史范围，压缩后的新消息与已完成执行仍保留；不撤销工具副作用。下一次请求照常判断自动压缩阈值，不关闭自动压缩。

### 3.11 不做

置顶内容（todo/plan）：没有生产者，以后有 plan/todo 工具时由工具侧在压缩后重新注入。

## 四、压缩对会话记录无感

- 总结请求的输入（含总结指令）与原始输出**都不存成消息**，会话记录里看不到那一轮。
- 落盘只有两样：`Boundary::Compaction`（summary、`keep_from`、文件快照、补充文字）和一条给用户的通知「已压缩上下文，保留最近 N 步」。
- 调用记录（`core_model_calls`）照常记一行：只有耗时、用量、成败，不含内容，用于用量统计与失败排查。

## 五、实体、写者与状态

| 实体 | 唯一写者 |
|---|---|
| `Boundary::Compaction { summary, keep_from, files, extra }` 及「已压缩」通知 | `compact` 操作 |
| 压缩边界的生效状态及撤回通知 | 同会话 worker：压缩成功时创建，撤回命令将其置为失效 |
| `Boundary::UserClear` 及「已清空」通知 | `/clear` 命令 |
| 压缩调用记录（`core_model_calls`） | `compact` 操作 |
| 模型上下文窗口 | Web 模型设置 |
| 触发百分比、保留 step 数 | Web 设置页 |

```
Idle ──输入/命令入队──▶ Claimed
Claimed(输入) ──────────────▶ Running ─┬─请求前超阈值─▶ Compacting ─成功（通知）─▶ Running
Claimed(输入, 先压缩) ─▶ Compacting ─┘                              └失败─▶ 结束（通知）
Claimed(/compact) ─▶ Compacting ─▶ 结束
Claimed(/clear) ─▶ 写 UserClear + 通知 ─▶ 结束
Claimed(撤回) ─▶ 目标为当前生效压缩 ─▶ 边界置为失效 + 通知 ─▶ 结束
             └▶ 目标已非当前生效压缩 ─▶ 报错，边界不变 ─▶ 结束
Running ─完成─▶ Idle（队列非空则回 Claimed）
```

压缩边界：创建即生效 → 用户撤回后失效；失效记录仍供历史展示，不参与上下文选择。后续 Boundary 只改变当前窗口的选择，不改写之前压缩的成败事实。UserClear 始终有效。

## 六、关键场景

**自动（长任务中途）**：第 k 次请求前，当前有效历史用量达到阈值 → 先压历史（待回答的新输入按 `extra` 处理）：沿用请求前缀 + 总结指令，过长时裁剪历史 → 解析总结与必读清单 → 通过 read 工具读文件快照 → 一个事务写 Boundary + 调用记录 + 「已压缩」通知 → 重读 `context_window` → 带上新输入发第 k 次请求。下一次按新窗口计算用量。

**手动带文字（微信）**：用户发 `/compact 接下来改部署脚本，先看 build.sh` → 入队 → 前一个 run 结束后认领 → `compact(文字)` → 正常回答这条输入。

**clear 后仍有输入**：A 正在执行 → `/clear` 入队 → B 入队并落盘 → A 结束 → 执行 clear，写空边界与通知 → 认领 B → 模型只收到清空后的上下文与 B，B 不因早于边界落盘而丢失。

**摘要不满意后撤回**：压缩成功，Web 显示「✓ 已压缩」 → 用户展开摘要后点撤回 → 撤回请求入同会话队列 → 轮到时将当前压缩边界置为失效并写通知 → Web 显示「已撤回」 → 后续请求恢复上一有效窗口，并继续包含压缩后的新消息。

## 七、不变量

1. 保留切点只落在 step 起点，不切开工具调用与结果（I1）。
2. 压缩输入读真相层，包含上一条 summary（累计）。
3. 同一会话同一时刻只有一个模型调用（含压缩调用）。
4. Boundary 与 summary、`keep_from`、文件快照、成功调用记录、「已压缩」通知一起原子写入；失败只记失败调用与通知，不改变上下文。
5. 历史展示不受 Boundary 影响，Web 可看完整记录，Boundary 显示为分隔条。
6. 窗口只由最新有效 Boundary 定义；保留 step 只从当前有效历史选取。只有显式撤回当前压缩才恢复此前窗口，不能越过 UserClear 恢复清空前的历史。
7. 待回答的新输入保留原文；指令之后排队的输入正常执行，不被压缩或 clear 丢掉。
8. 撤回只改变压缩边界的生效状态，保留摘要、快照、调用成败与用量，以及后续消息；边界失效与撤回通知原子落盘。

## 八、未知项（B2 前实测或定）

- `tool_choice: none`：DeepSeek / ChatGPT 订阅实测通过；OpenAI API key 的请求返回 401 invalid_issuer，未验证到参数，待有效凭据补实测；记录与复现命令见 B2 §一。
- 无上游用量时的中文字符／英文文本保守估算系数，以及历史裁剪的具体切点规则在 B2 明确；不通过两次调用的 `input_tokens` 差值估算保留 step，不引入大文件专项机制。
- N 的默认值（micbot 为 15）；总结提示词在中文长会话上实测一次。
- Web 命令补全清单由 core 提供；斜杠命令机制与微信 V2「跨 Channel 统一」合并在本项 B2 中，只带 `/compact`、`/clear`。
- 边界生效状态的存储表达、Web 结果展示与撤回接口合并进本项 B2；不新增撤回斜杠命令。
