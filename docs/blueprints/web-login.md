# B2：Web 改为登录制，取消 token

状态：实现完成，待验收。

来源：human 2026-11-11 提出。打开 Web 要用带 `#token=` 的地址，不方便；而且 iPhone 主屏幕应用的存储和 Safari 不共享，这种地址带不进去。改为登录制：管理员用户名为 `dzmfg`，密码按常规方式哈希存储，可以在网页上修改。Bearer token 整体取消。本文修订 [gateway](archive/gateway.md) §4.1 的鉴权部分。

## 行为

- **登录页**：未登录或登录已失效时，所有页面都显示登录页（用户名、密码、「登录」按钮）。登录后回到原来要打开的页面。
- **有效期 30 天，从最后一次使用算起**：只要 30 天内用过，就一直保持登录；超过 30 天没用，需要重新登录。重新登录会重新开始计算。
- **退出**：侧栏底部加「退出登录」。
- **登录失败**：提示「用户名或密码不正确」，不区分是哪一项错了。连续失败过多时暂时拒绝登录，见下文「限速」。
- **改密码**：设置里新增「账号」分类，填写当前密码和新密码（至少 8 位）即可修改。修改后其他设备都要重新登录，当前设备保持登录。
- **设置初始密码与找回**：在服务器上运行 `micnext [--config <配置>] --set-password`，按提示输入两次新密码（终端里不回显，脚本可经管道输入），效果和网页改密码相同。服务运行中也可以执行。
  - 首次部署还没有设置密码时，登录页提示「尚未设置密码：在服务器上运行 `micnext --set-password`」。
- **配置**：删除 `[gateway] token`。配置里还写着这一项时，启动报错，提示删掉它并用 `--set-password` 设置密码（同现有 `workdir` 的做法）。
- **启动提示**：终端打印 `Web 已启动：http://<listen>`，不再包含凭据。
- **删除**：地址里的 `#token=`、Bearer 校验，以及实时流的一次性票据（`*-ticket` 接口）。EventSource 会自动带上同源 cookie，不再需要票据。

## 契约

- **存储**：新增模块 schema `web`，首次启动时直接建表，不需要转换脚本。和 [web-push](web-push.md) 共用这个模块。
  - 单行表 `web_admin`：
    - `password_hash`：Argon2id 的 PHC 字符串。
    - `session_key`：32 字节随机值，按 `SecretColumn` 加密。每次改密码时重新生成，旧 cookie 随之全部失效。
  - 设置备份不包含 `web` 模块。
- **会话 cookie**
  - 名称为 `micnext_session`，值为 `<到期毫秒>.<签名>`，签名用 `session_key` 对到期时间做 HMAC-SHA256。服务端不存会话。
  - 属性：`HttpOnly; Secure; SameSite=Strict; Path=/; Max-Age=2592000`。线上经 HTTPS 访问；本机开发用 `http://localhost`（Chrome、Firefox 视为安全上下文，Safari 不接受，会登录不上）。
  - **续期**：鉴权通过的请求，如果 cookie 签发已超过 1 天，就在响应里重新下发一个 30 天的 cookie。这样最多每天续一次，不用每个请求都写。
- **限速**：进程内只计全局的登录失败次数。10 分钟内失败满 10 次后，在这个窗口剩下的时间里，登录接口一律返回 429「登录尝试过多，请稍后再试」。成功登录不清零。
  - 改用常规密码后，可能出现弱密码；服务又经公网 IP 访问，所以需要这层保护。
- **接口**：错误响应体同其他接口 `{"error": …}`。
  - `POST /api/login`（不需要登录）：
    - 请求体 `{ "username": string, "password": string }`。
    - 用户名为 `dzmfg` 且 Argon2 校验通过：返回 204，并下发 cookie。
    - 否则返回 401「用户名或密码不正确」。
    - 还没有设置密码：返回 409，提示设置方法。
  - `POST /api/logout`：返回 204，清除 cookie。
  - `PUT /api/account/password`：请求体 `{ "current": string, "new": string }`。
    - 当前密码不对：返回 400，不触发前端的过期处理。
    - 新密码少于 8 位：返回 400。
    - 成功：返回 204，并给当前设备下发新的 cookie。
  - 其余 `/api/*`（包括三个实时流）只认 cookie。缺失、签名不符或已过期时返回 401「未登录或登录已过期」。
- **前端**
  - 除登录接口外，任何 401 都切到登录页，并保留当前地址。
  - 登录接口的错误只在表单上显示。
  - 前端不再保存任何凭据。
- **CLI**：`micnext [--config <配置>] --set-password` 按配置找到数据目录直接写库，不需要服务在运行；库须由新版本服务启动过一次建好表。
- **其他**
  - 用户名、有效期、限速参数作为常量放在 gateway 的 `limits.rs`。
  - 新增依赖 `argon2`（RustCrypto，纯 Rust）。HMAC 用依赖树里已有的 `ring`。
  - 仓库里直接带 Bearer 调接口的脚本（`scripts/check-session-*.py`）改为先登录再带 cookie。
  - `scripts/db/convert.py` 登记 `web` 模块版本，以后升版本时按同样方式转换。

## 不做

- 多用户、服务端会话列表和单设备踢出、按 IP 限速。

## 验收

- 本地：`cargo fmt`、`cargo clippy -- -D warnings`、`bun run check`。接口用例覆盖：
  - 登录：成功返回 204；用户名或密码错误返回 401；未设置密码返回 409；第 11 次失败返回 429。
  - 鉴权：无 cookie、签名被篡改、已过期返回 401；超过 1 天的 cookie 会被续期。
  - 改密码：旧 cookie 返回 401，当前设备的新 cookie 可用。
  - 实时流：带 cookie 能打开。
- human：
  - 服务器上删掉 `token` 配置，用 `--set-password` 设置密码。
  - 在电脑浏览器和 iPhone 主屏幕应用里各登录一次。
  - 在网页上改一次密码，另一台设备回到登录页。
