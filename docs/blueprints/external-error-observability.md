# 外部交互错误链日志补全

状态：2026-10-21 human 批准依赖及方案；实现及本地验收完成，待真实环境人工验收。

## 目标与边界

覆盖模型 HTTP/流、微信 API/CDN、网页抓取、SQLite、磁盘文件与子进程。错误在转换为固定文案或业务枚举前，记录操作上下文与完整 source 链。日志不记录鉴权头、密钥、完整请求或响应；reqwest 错误先移除 URL。正常 EOF、取消、接收方退出和预期不存在不作为基础设施故障。

## 已实施（不改公开契约）

- OpenAI：请求、模型探测、HTTP client 初始化展开错误链；SSE 传输错误复用网络错误转换；非成功响应体读取/解析失败不再静默吞掉，保留 HTTP 状态，解析日志只记录类别与位置。
- 微信：传输失败提升至 WARN（正常长轮询超时保留 DEBUG），记录完整原因链及 timeout/connect/io_kind/os_error；保留现有面向用户的错误枚举；client 初始化、随机源、任务 join 失败在归类前记录原因；附件清理失败（除预期不存在）记录路径与错误。
- Web fetch：超时与重定向错误也保留原因链，移除错误中的 URL。
- Core：后台任务落盘/注册、子任务注册/跟进、额外服务故障日志展开错误链。
- Gateway：接口内部错误、channel setup/restore、事件回放、日志 SQLite 打开/写入展开错误链；更新子进程输出读取失败记录日志并显示在更新输出中。
- 启动 CLI 已逐层打印 source；主服务终止已使用 anyhow 完整链格式，无需重复修改。
- Store 的 SQLite/I/O 错误已通过 source 向上传递，由上述消费边界记录。密钥完整性失败沿用不暴露原始数据的业务错误。

## 已批准的公开契约：依赖

在 `mic-tool-fs`、`mic-tool-shell`、`mic-media` 新增 `tracing = "0.1"` 直接依赖，与现有工作区使用方式一致。不新增 crate、公开模块、公开类型/签名或 HTTP 接口。

调用方影响：保持现有工具结果、MediaError 分类和取消策略；新增 WARN/ERROR 诊断事件，由现有日志层采集。无需调用方适配。

## 已实施的边界补全

- 文件工具：终态 I/O 错误保留 action/path 与完整链，由 Core 记录；根目录探测和写入前 metadata 的非预期失败不再静默忽略。glob/grep 遍历、搜索和 mtime 错误每次调用汇总一条 WARN，记录失败次数与首个原因，不逐文件刷日志；预期不存在不告警。
- Shell：启动、等待、输出 sink 失败保留链，前台由工具调用消费边界、后台由任务终态消费边界记录一次。前后台输出管道读取错误单独记录 stream 与完整链；进程组终止失败除预期 ESRCH 外记录；不输出完整命令或环境变量。读取失败保持原有返回行为。后台输出库创建和读取失败也补全日志。
- 图片：格式探测、尺寸读取、解码、编码错误在转换为 MediaError 前记录阶段与完整错误链；不输出图片字节。正常格式不支持、大小限制与规整分支不新增告警。
