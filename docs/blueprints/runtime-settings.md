## 二、实体、写者与不变量

| 实体 | 写者 | 说明 |
|---|---|---|
| 人设 `core_personas` | 内置：启动同步；自建：Kernel（Web 设置页） | 软删除，行永不物理删除 |
| 对话偏好 `core_settings` | Kernel（Web 设置页） | 恰好一行 |
| 会话选择 `core_sessions.persona_id` | 建会话时 store 填默认或指定值；之后 Kernel（Web 选择器）；`claim_next` 遇已删除时改回默认 | |
| run 快照 `core_runs.persona_*`、`general_prompt`、`max_turns` | store 在 `claim_next` 同一事务写 | 写后不改 |

不变量：

1. 默认人设始终是未删除的人设；正被设为默认的人设不能删除；id 1 永不下线。
2. 名字在未删除人设中唯一；用户新建或改名为内置同名由 `NameTaken` 拒绝。
3. 每个会话恰好选着一个人设（可能已删除）；已删除不可被新选中；`claim_next` 遇已删除则改用默认人设并写回会话。
4. 每个 run 的设置在认领时一次读定；执行期间、并入的插话都按快照，不再读设置。
5. 迁移前的历史 run 快照列为 NULL；新 run 必有完整快照。

关键场景：

- **执行中切换**：run 7 用 A 执行中 → `PUT persona=B` 改会话行 → 插话并入 run 7 仍用 A → run 7 结束 →
  下一次 `claim_next` 读到 B，run 8 快照 B。
- **删除竞态**：会话选着 C 且有未认领输入 → 用户删除 C → 认领时 C 已删除，改用默认人设并写回会话，run 快照为默认人设。

## 四、阶段二草案：模型设置

阶段一落地后细化成正式契约。方向与结构：

- **模型条目**入库 `core_models`（名字、`kind`、该 kind 自己解析的配置 JSON、key 来源、软删除），只经 Web 增删改；
  设置里的默认模型、会话的 `model_id`、run 快照（条目 id 与名字；请求模型名已在 `core_model_calls`）与人设同构。
  新会话用标为默认的条目（store 保证恰好一条）。`config.toml` 的 `[models]` 在新路径落地的同一次改动里删除，旧写法报错指向设置页。
- **Provider 工厂**（正交审查 A2）：Module 只登记 `kind` 对应的工厂（校验配置 + 由条目创建 Provider），运行期按 run 的快照创建实例；
  删除装配期靠 provider 数量反推模块类别的逻辑与 `[models]` 解析。具体配置形状仍由懂协议的 Provider 解析，core 不接管服务商字段；
  更新模型不得重跑包含 Service/迁移的整次 install。
- **key**：`Stored(密文) | Env(变量名)` 显式二选一（常见预设默认 `Env` 并预填变量名，不用回退顺序）；
  本机主密钥文件（0600，不在数据目录）+ AES-GCM，只防库单独泄露，主密钥丢失明确报错；Web 只写不读，日志不出现 key。新依赖（AES-GCM）在契约里列出。
- **首次运行**：没有模型时服务照常启动，网页提示先添加模型；`-p` 报错指向设置页。配错或失效即该次 run 失败。
- **预设**：经 `/models` 拉取模型、上下文窗口、模态与推理档位（阶段二之后），只留主要参数给用户填。
- 待定：工厂 trait 签名、配置 JSON 版本化、Web 表单是否由 kind 描述字段、实例是否缓存；条目身份、请求模型名、推理兼容身份是否需要不同表示
  （当前只用请求模型名比较，不足以证明跨服务商同名兼容，但现在只有固定 Provider）。
