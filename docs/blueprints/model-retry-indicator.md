# B2：运行指示显示模型重试

状态：2026-10-23 实现完成，本地检查通过，待 human 页面与真实链路验收。

来源：human 2026-10-23 提出。链路不稳时模型调用会自动重试（最多 3 次，等 2s、4s），但页面只显示"让我想想…"和计时，用户分不清是在思考还是在反复失败。

## 展示

运行指示的文案旁用弱化的小号文字显示 `第 2 次重试`，不加底色、边框或额外动画。

- 等待重试期间，计时位置改为倒计时 `3s 后重试`；倒计时结束后恢复原有阶段累计计时，重试次数保留。倒计时只表达后端告知的预计等待，不用于驱动重试。
- 不展示重试中的错误原因；最终失败继续走现有失败通知与 UI。
- 回复落库、压缩完成、失败通知落库或 run 结束时清除提示。
- 对话调用与压缩（含手动 `/compact`）都显示；标题生成不在运行指示里，不涉及。

## 契约

- **core**：`KernelEventKind` 新增 `ModelRetrying { attempt: u32, delay_ms: u64 }`。在 `retry_wait` 决定重试时发出，`attempt` 为即将进行的第几次重试（首次调用失败后为 1，不是调用尝试序号），`delay_ms` 为实际选定的等待毫秒数。对话与压缩共用这一个出口。
- **Gateway SSE**：新增事件 `model_retry`，字段同上。
- **重连**：不修改 `ready`，不查询或恢复历史重试状态；连接断开时清除临时提示，重连后只展示新收到的重试事件。
- **Web**：直接展示后端给出的重试次数，并按收到事件的时间和等待时长做临时倒计时；不累计失败次数、不判断是否重试、不查询调用记录。错误原因本次不增加字段，后续有展示需要时再定。

无存储结构变更，无 Provider 变更。

## 验收

- 本地：core 功能测试覆盖可重试失败发出事件、不可重试或已到上限不发出；`cargo fmt`、`clippy`、`bun run check`。
- 本地：验证前端展示后端给定的次数，倒计时结束恢复原计时，回复、压缩完成、失败通知、run 结束及断线清除提示。
- human：服务器链路不稳时观察对话和 `/compact` 的次数与倒计时，确认展示轻量、最终失败仍显示现有失败原因。
