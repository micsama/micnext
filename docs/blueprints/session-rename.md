# B2：手动修改会话标题

状态：已批准（不做 `/rename`、侧栏不加入口），已实现，待验收（2026-11-12）。

## 为什么要做

标题现在只能由模型生成：首条文字输入后自动生成一次，之后只能点 ↻ 让模型重来。模型起的标题不贴切时，只能反复重新生成碰运气。长期使用的会话（例如固定用途的会话 54、46）更需要一个自己定的名字，方便在侧栏和 ⌘K 里找。

代价小：一个接口、一个存储写入，前端在已有的标题位置上加编辑。标签已有「手动优先」的先例（`tags_manual`），标题沿用同样的语义，不需要新列。

## 行为

- 会话页标题栏点标题，原地变成输入框，内容为当前标题并全选。Enter 或失焦保存，Esc 放弃。手机上同样点按。
- 去掉首尾空白后为空，或与原标题相同，都不发请求，直接退出编辑。超过 40 字（与生成标题同一上限 `TITLE_CHARS`）由服务端返回 400，错误显示在标题栏下方现有的错误行。
- 可编辑的条件与 ↻ 相同：主会话、未归档、不是定时任务会话。
- 手动标题不会被自动覆盖。自动生成只在会话还没有标题时触发，现状已经如此。点 ↻ 仍会用模型标题替换，这是用户的明确操作。
- 保存时如果正在生成标题，先取消生成，再写入，避免生成结果随后把手动标题盖掉。
- 只改标题，不动标签和 `title_error` 以外的字段。保存成功时清掉 `title_error`。
- 其它标签页和设备的侧栏通过现有的会话变更事件同步。

## 契约

- **Gateway**：新增 `PUT /api/sessions/{id}/title`，请求体 `{ "title": string }`（`deny_unknown_fields`），成功返回 204。会话不存在返回 404，已归档或非主会话沿用生成标题的同类错误，标题为空或超长返回 400。现有 `POST /api/sessions/{id}/title`（重新生成）不变。
- **mic-core**：`Kernel::rename_session(session, title)`。依次检查会话可用且为主会话、校验标题，`titles.stop(session)` 取消进行中的生成，写入，发 `SessionChanged`。
- **mic-store**：`set_session_title(session, title)`，写 `title`，清 `title_error`。
- **Web**：`api/client.ts` 加 `renameSession(id, title)`；`SessionView` 加 `rename(title)`，成功后走现有的 `#refreshTitle`；`Header` 的标题支持编辑，由 `ChatView` 传入是否可编辑及保存回调。
- 不改数据库结构，不加依赖。

## 不做

- **`/rename` 指令**：现有指令（`/compact`、`/clear`、`/stop`）由服务端定义，作用于运行队列，微信渠道也共用。标题只在 Web 上可见，`/rename` 放进服务端指令表，微信里能用却看不到效果；只在前端拦截，又会让补全列表和服务端指令表分成两个来源。点击标题已经覆盖这个需求。
- **清空标题、退回预览**：清空后不会再自动生成，等于让会话永久没有标题，没有实际用途。
- 侧栏 ⋯ 菜单里的「重命名」：先只做标题栏一个入口，用下来不够再加。

## 实现记录

- 标题校验为 mic-core 的 `SessionTitle::parse`，错误是 `TitleError::Blank` / `TooLong`，网关映射为 400。
- 取消生成复用归档时的 `titles.stop`：被取消的那次生成仍按现有路径记一条失败调用，`title_error` 随后被改名清掉。取消原因的文案从「会话已归档」改为「标题生成已取消（会话归档或手动改名）」。
- 前端成功后先把新标题写进当前视图，避免退出编辑时闪回旧标题。标题栏下的错误行前缀从「标题生成：」改为「标题：」，生成和改名的错误共用这一行。输入法组字时的 Enter 不触发保存。

## 验收

- 本地：`cargo fmt`、`clippy`、`bun run check` 已通过。没有起本地实例逐个请求接口。
- human：点标题改名，侧栏和另一个标签页同步更新；改名后再发消息不会被自动标题覆盖；生成标题途中改名，最后保留的是手动标题。
