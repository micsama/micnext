# B1：会话列表——置顶、标签、后台更新提醒

**状态：方向待 human 定（2026-10-22）。**

## 诉求

1. 置顶会话，单独分组。
2. 会话打标签，与生成标题合在一次调用。
3. 后台会话有新消息时，侧栏亮红点。

侧栏宽 18rem，一行只放得下标题和悬停时的「⋯」，要先定好每行放什么、放在哪，再加功能。

## 现状

- 侧栏按「今天 / 昨天 / 最近 7 天 / 更早」分组列 Web 会话；微信、CLI 收在「其它渠道」折叠里。定时任务会话不进侧栏，只在任务页里能进。
- 侧栏只在切换会话、窗口获得焦点、当前会话跑完时重拉。**后台会话有新回复，侧栏不会变**，排序也不会动，要切一下才更新。
- 全局 SSE 目前只发推送和定时任务事件。
- 标题只在首条文字时自动生成一次，可以手动重新生成。模型只输出一行纯文本。

## 行布局（三项共用，先定）

推荐**仍然单行**，左右各留一个固定小槽，标签不进行内：

```
 ● 帮我看下 nginx 配置为什么 502        ⋯
 ◌ 周报整理                           ⋯     ← 运行中（转圈）
   Rust 生命周期问题
```

- **左槽 8px：状态点。** 有未读就显示主色实心点，同时标题加粗（Slack / Telegram 的做法）；会话在后台运行中显示一个小转圈；都没有就留空。未读优先于运行中。
- **右槽：悬停才出现「⋯」**，和现在一样。菜单里有置顶 / 取消置顶、编辑标签、重新生成标题、归档。
- **标签不放在行里**，作为侧栏顶部的筛选条（见下文）。如果每行都带一两枚标签，18rem 里标题只剩一半，而且满屏小色块会抢走红点的注意力。

备选是两行（标题 + 一行「标签 · 时间」），像邮件列表那样。一屏能看到的会话数会减半，不推荐。

## 1. 置顶

- 侧栏最上面一个「置顶」分组，下面是原来的日期分组；置顶的会话不在日期分组里重复出现。
- 置顶不分页，一次全部列出；按置顶时间排，新置顶的在上面。不做拖拽排序。
- **置顶跨渠道**：微信会话也可以置顶，置顶后出现在顶部分组里，不再藏在「其它渠道」折叠中。这也是给常用的微信对话一个顶层入口。
- 存储：`core_sessions.pinned_at` 可空。归档会同时清掉置顶。

## 2. 后台更新提醒

**什么算未读**：Web 会话中出现了新的 `Reply` 或 `Notification`，并且这些消息晚于你最后一次看这个会话的时间。你自己发的消息、工具调用过程不算。

**只给 Web 会话亮点。** 微信的回复你在微信里已经看过了，Web 侧栏再亮点就是噪音；CLI 同理。定时任务的结果已经走通知中心，不在侧栏重复提醒。

**什么时候算已读**：会话在前台打开、浏览器标签页可见时，新到的消息直接算已读；标签页切到后台时到达的，等你切回来再算。

**存在服务端**：`core_sessions.seen_message_id`，手机和电脑共用同一个已读状态。列表接口返回 `unread: bool` 和 `running: bool`。

**实时性**：全局 SSE 增加 `session_activity { id }` 事件，在 Root 会话写入 Reply / Notification、运行开始或结束时发出。Web 收到后重拉侧栏首页。复用现有的「事件只带 id、客户端重拉」模式，不推送增量数据。

**折叠和窄屏**：
- 「其它渠道」折叠时，如果里面有置顶以外的运行中会话，折叠标题上显示一个弱化的转圈。由于未读只针对 Web 会话，折叠里不会出现红点。
- 手机上侧栏是抽屉，平时看不到。只要有任意未读，顶栏的菜单按钮上就显示一个红点（和通知铃铛分开，铃铛只管推送）。

## 3. 标签

这一项分歧最大，需要你来定。标签的价值在于**能按标签筛选**，前提是标签数量收敛。如果模型每次随手起名，很快就会出现「Rust / rust / 编程 / 代码」并存，筛选也就没有意义了。

| 候选 | 做法 | 优点 | 问题 |
|---|---|---|---|
| A 自由生成 | 生成标题时一并输出 1–2 个标签，有新词就直接建 | 零配置 | 标签会越来越多，过一阵就得手动合并 |
| **B 受控词表（推荐）** | 你在设置里维护一份标签列表（比如工作 / 学习 / 生活 / 代码）；模型只能从中选 0–2 个，都不合适就不打；你也可以在菜单里手动改 | 筛选条稳定、短；不会自动生出新词 | 首次要先建几个标签；词表为空时不打标签 |
| C 单一分类 | 每个会话最多一个分类，相当于文件夹 | 最简单，甚至可以替代日期分组 | 一个会话涉及两件事时没法表达 |

推荐 B。由模型推荐新标签、你确认后加入词表的做法要多一套交互，先不做。

**和标题合并**：自动标题（首条文字）和手动「重新生成标题」时，模型改为输出 `{ title, tags }`，tags 只能取自当前词表。以下情况不覆盖标签：
- 标签是你手动改过的，以后重新生成标题也不动；
- 词表为空时，调用和现在完全一样，只出标题。

**展示**：
- 侧栏顶部一排筛选标签「全部 · 工作 · 学习 …」，只在词表非空时出现，单选。选中后，置顶分组和日期分组都只显示带这个标签的会话。这需要服务端按标签过滤，因为列表是分页的。
- 会话页顶部标题旁显示这个会话的标签，可以点击编辑。

存储：`core_tags(id, name, color)` 和 `core_session_tags(session_id, tag_id, manual)`。

## 拆分与顺序

三项沿着三个独立的方向变化，分开写 B2、分开验收：

1. **侧栏行布局 + 后台更新提醒**：先做这个，收益最直接，也定下左右槽的位置。
2. **置顶**：小，可以和第 1 项合进同一个 B2。
3. **标签**：等你选定 A / B / C 后单独写 B2，涉及标题生成的输出格式和设置页。
