# B1：后台任务与子 agent

**状态：review 已完成，已起 [B2 草案](../blueprints/async-jobs.md)（2026-10-16），待批准。不是实现授权。**

review 后 human 确认：子 agent 是可休眠、可继续 query 的 session，不以交付作为 session 终态；默认隐藏较久未活动的子 session，具体 7/14 天在 B2 定。归档停止主/子 session 的执行和后台 shell，历史保留。重启只留用户可见的中断记录，不自动唤醒；未来定时任务另定。费用在 trace 用“包含子 session”开关控制范围。下文原提案与这些决定冲突处，以此记录和 B2 为准。

## 一、要解决什么

1. **后台 shell**：命令派出去跑，agent 不死等。
   - 耗时脚本：比如处理一批数据，跑完要拿结果。
   - 长期运行的程序：比如帮用户起本地 dev server。
2. **子 agent**：把「过程冗余、结论紧凑」的任务分出去，父上下文只拿到结论，不堆积中间过程。
   - 适合外派：遍历、试错、调研这类任务。
   - 不适合外派：需要主 agent 每步盯着方向的任务，比如调一个微妙的 bug。
   - 外派与否由模型判断，提示词里写清上面这条判据。
3. 两者做完后，结果回到发起它的会话，并唤醒 agent 接着处理。运行期间，agent 和用户都能查看、管理它们。

## 二、用户看到的效果

- 让 agent「把网页跑起来」：它起 dev server 后马上回复「已启动」，对话照常继续。服务一直跑着，直到被杀或 micnext 退出。
- 让 agent「调研三个方案」：它派出三个子 agent 后先回复「已分头去查」，可以继续聊别的。每个子 agent 交付时，agent 被唤醒，汇总后告诉你。
- 父 agent 可以对已交付的子 agent 追问：「第二个方案的价格再查细一点」。
- Web 聊天页右侧有一个任务小列表，列出当前会话名下的子 agent 和后台 shell，展示状态、耗时、最近输出，可以手动杀掉。
  - 子 agent 可以点进去，看它的子会话过程。
- 停止键只停当前这一轮，不动后台任务。
- 归档会话前，如果还有任务在跑，提示「还有 N 个任务在运行，归档会终止它们」，确认后杀掉。

## 三、方案

### 3.1 两种任务，共用一套管理

后台 shell 和子 agent 是两种「任务」：派出、查询、读输出、杀掉、做完回注，都走同一套。管理工具和 Web 列表也只认这一种实体。两者的区别在于寿命：

| | 后台 shell | 子 agent |
|---|---|---|
| 载荷 | 一个进程组 | 一个子会话（`Root` 之下） |
| 状态 | 运行中 → 完成 / 失败 / 超时 / 被杀 / 中断 | 运行中 ⇄ 待命（已交付，可追问）→ 被杀 / 中断 |
| 什么时候回注 | 进程结束 | 子会话每跑完一轮（首次交付和每次追问后都算） |
| 输出 | 落盘文件 | 子会话自身的记录 |

- 子 agent 就是子会话，trace、用量、停止键直接复用现有机制，不另做一套。
- 以后定时任务的每次运行也是「子会话加一份完成事实」，到时候评估能否复用。

### 3.2 所有权与可见范围

- 任务归发起它的会话，结果只回注给发起者。
  - 子 agent 起的后台 shell 结束时，唤醒的是这个子 agent，不是它的父会话。
  - 子 agent 被唤醒、处理完之后，按 3.1 再向父会话回注一次。
- 管理范围是「自己加整棵子树」：根会话能查询、读输出、杀掉所有后代的任务；子 agent 只能管它自己名下的。
- 杀子 agent 时，连带停掉它当前的那一轮，杀掉它名下的全部任务，状态记为被杀。

### 3.3 回注：沿用现有执行主路径

现有契约已经覆盖回注所需的消息与顺延规则：

- [mic-message](../blueprints/archive/mic-message.md) §三把 `Completion` 定义为「可认领、进模型上下文」的消息。
- 派出时，工具调用立即以 `Dispatched { exec_id }` 闭合。
- [run-execution](../blueprints/archive/run-execution.md) §4.4 已有顺延规则：工具结果出来之前到达的消息，排到结果之后。

回注就是写一条 `Completion`、再发一次 `Wake`：

- 发起会话正在跑：在下一个模型调用边界并入，也就是现有的「边界插嘴」。
- 发起会话空闲：认领这条消息，开一个新 run。
- run 刚结束、回注恰好此时到达：由调度表的 `Dirty` 状态接住。
- 任务终态与 `Completion` 在同一事务里写入，所以只会投递一次。

pi 把投递分成 steer / followUp / nextTurn 三档，我们只要一档：插嘴边界已经覆盖了它的默认档。

谁杀的决定回不回注：

- 模型自己杀的，不回注，它知道自己杀了什么。
- 用户在 Web 上杀的，回注「已被用户终止」，免得 agent 一直等。

### 3.4 资源控制

| | 主控 | 防卡死 |
|---|---|---|
| 后台 shell | 超时，有默认值；dev server 一类由模型显式声明不限时 | 同左；另有提醒正则（§五） |
| 子 agent | `max_turns`，默认比主会话小，直接对应成本；交付内容另设长度上限 | 每轮设墙钟超时，给得宽松 |

- 子 agent 默认配置：用同一个模型，不带人设，只带任务说明和精简过的工具表。
- 提示词要求子 agent 的最后一条回复就是交付物，因为只有这条会进父上下文。

### 3.5 输出

- 后台 shell 输出短的，直接放进回注；长的全量写入文件，回注里只带尾部几行和文件路径。模型需要细节时，用读输出工具或 `read` 去取。
- 子 agent 只回注它最终的回复，中间过程留在子会话里。

### 3.6 工具面（命名与参数在 B2 定）

- **`bash` 增加后台执行模式**：在边界解析成强类型的执行模式，默认仍是前台；不另开一个工具。
- **子 agent 工具**：派出一个新子 agent，或给已有的子 agent 追问。
  - 默认异步，返回任务 id。
  - 同步等待留出接口，但不作为默认。
- **管理工具**：列出任务、读输出（按尾部或偏移）、杀掉任务，范围见 §3.2。
- **防递归**：子会话的工具表里不放子 agent 工具，所以它根本调不了子 agent，不需要深度检查。后台 shell 照常可用。

### 3.7 退出与重启

- micnext 退出时，后台进程一起结束；子会话的 run 按现有崩溃收尾处理。
- 重启后，没跑完的任务一律收尾为「中断」，并向发起会话回注一次，让 agent 知道这个结果不会再来了。
- 这与「未知副作用不重放」一致：不自动重新拉起任何任务。

## 四、以后再做

- **提醒正则**：派后台 shell 时，模型可以选填一个正则，输出一旦命中，就回注一次进展，按次数和间隔限流。用来发现长任务卡住或出错而 agent 不知道的情况。框架层面不做「长时间无输出」的检测。
- **子 agent 起后台任务的限制**：第一版不限制，用下来再看。
- **codemode**：模型写一段脚本，在沙箱里循环调用工具，中间过程不进上下文。
  - 现阶段用 `bash` 跑 python 脚本已经够用。
  - 等出现只存在于 micnext 内部的工具（`send_message`、记忆、MCP），再评估要不要做。
  - 到时语言选嵌入式 JS：QuickJS 直接打进二进制，不依赖宿主环境；嵌入 Python 的各种方案都偏重。

## 五、不吸纳（对照 pi）

- **多档投递、requestId 去重**：分别由插嘴边界、事务替代，见 §3.3。
- **用进程隔离子 agent**：子会话与主会话同进程，走同一个调度器，不另起进程。

  - 子 agent 工具与管理工具。
  - 子会话的工具表与提示词。
- `mic-gateway` / Web：
  - 任务列表接口，以及聊天页右侧的任务列表。
  - 归档前的「仍有任务在跑」提示。
