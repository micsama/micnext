# B2：Web 推送站内提醒

**状态：已批准（human 2026-10-20），已实现，待页面验收。** 原型：`tmp/push-banner-preview/index.html`，横幅选方案 A（铃铛下卡片）。

## 方向

现有 Web 推送只有通知中心红点，容易错过。补上未读数字、到达动效和站内横幅，让 agent 主动推送能被注意到；普通聊天回复不触发。不做浏览器系统通知（侵入性强，且要求 HTTPS），不加开关。

## 行为

- **数字徽标**：铃铛红点改为红色数字，显示未读数，超过 99 显示 `99+`；无未读时隐藏。
- **到达动效**：新推送到达时铃铛短暂摆动、徽标轻弹，随后停止；遵循系统的减少动态效果设置。
- **站内横幅**：新推送到达时从铃铛下方落出一张卡片（尖角指向铃铛），含来源会话标题（为空时用会话编号）、正文摘要、「打开」「收起」。
  - 不自动消失；「打开」展开通知中心并收起横幅，「收起」只隐藏横幅，不标已读。
  - 多条合并为一个横幅：只有一条时显示其摘要，多条时显示「N 条新推送」和最新一条摘要。手动收起后，下一条新推送重新显示。
  - 通知中心已打开时不挂横幅；打开通知中心清除当前横幅。
  - 状态在全局通知中心，各页页头的铃铛都渲染它，切换页面不消失。
- **哪些算新推送**：首次加载时记下最大推送 id，之后 id 更大且未读的才提醒。首次加载的历史不提醒；SSE 重连补拉到的按同一规则合并进横幅。
- 已读规则不变：通知中心展开时看到的标已读。
- **补充（human 2026-10-20）**：Web 通知中心收下全部推送，不再是 `push` 的可选去向；只发微信的推送在 Web 也计未读、也提醒。契约改动记在 [scheduled-tasks.md](scheduled-tasks.md) P1，旧数据由 core 迁移 17 清理。

## 契约

横幅与动效只改前端；Web 去向的取消见上方补充。

- `web/src/state/pushes.svelte.ts`：识别新推送，持有横幅状态与通知中心开合状态（横幅「打开」要能展开它）。
- `web/src/components/PushBell.svelte`：数字徽标、动效与横幅，开合状态改用统一状态。

## 验收

- `web/` 下 `bun run check`。
- human 在浏览器验收：数字徽标与 `99+`、动效与减少动态效果、横幅单条与多条合并、打开与收起、通知中心已打开时不挂横幅、首次历史不提醒、重连补拉合并、窄屏布局。
