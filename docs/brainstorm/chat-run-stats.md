# B1：聊天统计行与上下文占用

**状态：方向已定（2026-10-15 human），进入 [B2](../blueprints/archive/chat-run-stats.md)。**

## 问题

聊天页看不到一轮花了多久、用了多少 token、缓存命中如何，也看不到上下文离自动压缩还有多远；这些事实 trace 已经采集（调用起止、首次输出、用量、工具起止），只在开发者页能看。

## 已定

| 问题 | 决定 | 理由 |
|---|---|---|
| 粒度 | 每轮一行，挂在该轮最后一条消息下；生成中不显示，结束后出现 | 一轮是用户感知的单位；逐调用会刷屏，细节去 trace |
| 内容 | 步数与工具数、总耗时（模型 / 工具）、首字、输出速率、token（输入 / 输出）、缓存命中率、费用 | 与 trace 运行概览同一组事实 |
| 口径 | 后端一处计算，聊天与 trace 运行概览共用；缺失的用量不当零，标未知 | 一处真相，避免两页数字对不上 |
| 上下文占用 | 输入框旁显示「已用 / 窗口」与自动压缩阈值，口径即压缩触发的估算 | context-compaction B2 已约定圆环复用该计算 |
| 前端形态 | 由前端自定，后端只给数 | 交互随时可调，契约只管数据 |

## 不做

- 不新增采集：只用 trace 已有事实。
- 不显示逐次请求、重试明细，点进 trace 看。
- 看板聚合不改。
