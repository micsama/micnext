# B1：预测用户的下一句输入

状态：方向已定（2026-10-28），待写 B2。

回复结束后，猜用户接下来最可能说的一句话，例如「继续」「按方案 A 实现」「提交推送」，用户一键就能填进输入框。生成用共享的杂活模型。

## 一、改名：标题模型改为杂活模型

只改共享的模型配置，单独做一个 B2，先于预测功能完成。

- **改**：配置、数据库、接口和备份里的 `title_model` 都改成 `utility_model`。
  - 数据库：`core_settings.title_model_id` 和 `title_reasoning_effort` 改成 `utility_*`，用独立的转换脚本完成，由 build.sh 在停服务后执行，不编进二进制。
  - 接口：`/settings/title-model` 改成 `/settings/utility-model`。
  - 设置页：分组改叫「杂活模型」。
- **不改**：标题生成自己的类型和调用用途继续叫 `title`。它只是杂活模型的一个用途。

## 二、触发范围

- **生成**：Web 主会话里的普通对话 run 正常结束后，在后台生成。
- **不生成**：
  - run 失败或被停止；
  - 回复以 `ask_user` 结束、正在等用户回答；
  - 清空、压缩等指令 run；
  - 子 agent 会话和微信会话。

## 三、输入与输出

- **输入**：最近 3 轮，去掉工具调用和思考过程；发出前和普通对话一样做凭据脱敏。
- **输出**：单个候选，一句话，用用户的语气，不加解释。猜不出时输出空，界面就什么都不显示。
- **记账**：作为旁路调用记在模型调用表里，看板能看到花费。

## 四、异步与收尾

- **只放内存**：候选按会话放在内存里，不持久化，重启后丢失。
- **关联来源 run**：候选带上生成它的 run。下面两种情况发生后，候选即使才返回也不再展示：
  - 用户已经开始输入；
  - 新一轮已经开始。
- **调用策略**：设超时、不重试。会话归档或服务停止时取消调用。
- **失败处理**：失败只记日志，不影响主对话，界面不提示。

## 五、交互：输入框里的灰色提示

- **展示**：输入框为空时，用灰字显示候选，灰字前加 ✦ 标记，和普通的占位提示区分开。
- **接受**：按 Tab 填入候选，再按回车发送。
  - 只有灰字可见、并且不在输入法组合输入中时，Tab 才接受候选；其余时候 Tab 保持原有行为。
  - 手机上没有 Tab 键，在灰字末尾放一个小的「填入」按钮。
- **忽略**：直接打字，灰字就消失。
