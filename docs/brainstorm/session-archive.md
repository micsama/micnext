# B1：会话归档（列表移除，记录保留）

**状态：方向已定（2026-10-13）；human 要求从简，归档后收到新消息仍保持隐藏。已起 [B2](../blueprints/session-archive.md)，待批准，尚未实施。**

## 诉求

前端可归档/删除会话，后端不删除任何数据，只标记，以便手工恢复。推荐界面只提供一个「归档」动作，避免两个名字对应同一语义；不做永久删除或另外一套删除状态。

## 推荐候选

- 在侧栏会话条目的菜单中提供「归档」，当前打开会话归档成功后回到新会话页。
- 仅 Root 会话可归档；Web、微信、CLI 统一。后端存 nullable `archived_at`，侧栏列表排除有标记的会话。
- 会话、消息、模型调用和设置全部保留；归档不取消执行中的正文或标题任务，也不更改最近消息时间。后台完成后仍受标记控制，不会因标题更新重新加入侧栏。
- 已归档会话收到新消息仍保持隐藏，手工清除标记恢复。
- 归档仅影响列表可见性，已知会话 URL 仍可查看。暂不加归档列表或 Web 恢复按钮，手工将 `core_sessions.archived_at` 清为 NULL，再刷新列表即可恢复。

## 进入 B2 时的契约范围

明确标记列与 Root 权限、归档命令/HTTP 状态码、列表查询过滤、会话详情标记、前端导航与分页缓存处理，以及收到新消息时的恢复规则。归档和标题独立实施与验收，不把隐藏规则塞进标题生成流程。

本地可验收：归档后列表不出现、详情/消息保留、重复归档、执行中归档、微信入站后的规则、手工恢复及列表分页不漏项。页面菜单观感交给 human。
