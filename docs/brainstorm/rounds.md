# B1：统一「轮」的口径

状态：候选待定（2026-10-28）。

「轮」现在在不同地方指三种东西，同一个页面里都会混用。下面先列现状，再给候选。

## 现状

| 位置 | 写法 | 实际指 |
|---|---|---|
| Trace 轮次列表、「N 轮」、轮次图表 | 轮次 #13 | 一个 run |
| 侧栏、Trace 会话异常 | 调用失败 N 轮、中断 N 轮 | run |
| 会话页、设置 | 下一轮生效、下一轮用的模型 | 下一个 run |
| 设置「单轮调用上限」（`max_turns`） | 单轮调用上限 | 一个 run 内的模型调用次数 |
| Trace 结束状态 `MaxTurns` | 轮数上限 | 同上，指调用次数用尽，不是 run 数 |
| 会话页分页 `PAGE_ROUNDS`、预测取材 `PREDICTION_ROUNDS` | 最近 N 轮 | 按 `UserInput`/`Trigger` 计数 |
| 会话页每条 AI 回复下的复制和统计 | （无名） | 一次模型调用（一步） |

具体摩擦：

- **Trace 里自相矛盾**：「轮次」是 run，但结束状态「轮数上限」说的是模型调用次数。
- **分页和取材按输入计轮**：连发两条被一个 run 一起领走，Trace 里算 1 轮，分页和取材算 2 轮；`ask_user` 的回答会开新 run，但用户感觉还在同一个问题里。
- **会话页的复制和统计挂在每一步上**：一个 run 里模型调了 5 次工具再回答，就有 5 组时间、token 和缓存命中，复制按钮也只复制那一步的文字。用户关心的往往是「这一轮花了多久、多少钱」，以及复制最终回答。

## 候选

### 1. 用词

固定三层，界面和代码注释统一：

- **轮**：一个 run，从领取输入到结束。
- **步**：轮内的一次模型调用（含工具），重试叫「尝试」。Trace 已经这样用。
- **条**：按输入计数的地方不再叫「轮」，直接说「最近 N 条输入」。

随之改的文案：「单轮调用上限」→「每轮步数上限」；`MaxTurns` 显示为「步数用尽」。这两处只改展示，不改设置字段和存储值。

### 2. 分页和取材按什么数

- **A 维持按输入计数，只改名**：改动最小，分页手感不变；和 Trace 的轮数对不上，但名字不再冲突。
- **B 改为按 run 计数**：消息表已有 `run_id`，分页和 Trace 的「最近 5 轮」完全一致；需要改 `messages_page` 的切分，属于 store 公开签名变化。

倾向 A：按输入切页对聊天页面本来就自然，统一的重点是名字不冲突。

### 3. 会话页的复制与统计

- **A 维持每步一组**：信息最全，但多步时重复、吵。
- **B 每轮一组，挂在收尾回复下**：复制最终回答；统计显示整轮耗时、总 token、费用；中间步骤只在悬停或 Trace 里看。工具多的轮次会清爽很多。
- **C 每轮一组 + 每步保留极简信息**：中间步骤只留时间，收尾处给整轮汇总。

倾向 B：和 Trace 的「轮次」对齐，用户看到的「一轮」就是一次提问到回答；每步明细已经在 Trace 里。整轮汇总需要前端按 run 聚合，或者回放数据带上 run 的统计，属于 B2 再定的细节。

## 待 human 定

2. 分页按输入（A）还是按 run（B）。
3. 会话页复制与统计取 A、B 还是 C。
