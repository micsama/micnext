# B2：推送加标题

状态：实现完成，待验收。

来源：human 2026-11-11 提出，系统通知要像正规通知一样有标题和正文。现在系统通知的标题借用来源会话标题，看不出这条推送说的是什么。human 选定方案：标题由出推送的一方给出（模型或框架），harness 不另外生成标题，也不靠约定从正文里截取。修订 [web-push](web-push.md) 的「通知内容」和 [scheduled-tasks](scheduled-tasks.md) P1 的推送结构。

## 行为

- **每条推送都有标题**：一句短话说清这条推送的事，比如「部署完成」「需要你确认迁移方案」。正文是独立可读的纯文本。
- **系统通知**：标题就是推送标题；正文是推送文字，截到约 200 字。点开后进入来源会话，这一点不变。
- **通知中心**：每条推送的第一行仍然是来源会话名（小字，可点击），下面是加粗的推送标题，再下面是正文。新通知横幅显示标题，不再显示正文开头。
- **微信等 IM**：发出的内容是「标题、空一行、正文」。IM 消息没有单独的标题字段，所以标题作为正文的第一行。
- **框架推送**：现在只有定时任务结果一种，标题是「⏰ <任务名>」，同样不超过 15 字，任务名过长时截断并补「…」；正文是「定时任务「<全名>」<结局与原因>。」。

## 契约

- **`push` 工具**：新增必填参数 `title`。
  - 去掉首尾空白后不能为空，不能换行，最多 15 字（`limits.rs` 的 `PUSH_TITLE_CHARS`；锁屏标题只占一行，human 按真机观感定）。不符合时返回输入错误，提示模型改正，不替它截断。
  - `text` 的参数说明补上「纯文本，不用 Markdown」。通知中心、微信和系统通知都按原样显示文字，不会渲染 Markdown。
- **mic-store**
  - `core_pushes` 新增 `title TEXT NOT NULL`。
  - `NewPush` 和 `PushView` 都加上 `title`；`PushView.source_session_title` 保留，供通知中心显示来源。
  - 推送发往 IM 时，`MessageBody::Notification` 的 `text` 写成 `{title}\n\n{text}`，`MessageBody` 的结构不变。
  - core schema 版本 32 → 33。转换脚本 `scripts/db/core-33.sql` 给已有推送补标题：取来源会话标题，没有就用「通知」。
- **mic-core**：`Pushes::send` 和 `Pushes::notify` 都新增 `title` 参数；定时任务的 `report` 按上面的格式传入标题。
- **mic-gateway**
  - 推送接口的返回里多一个 `title` 字段。
  - Web Push 载荷 `{title, body, url}` 的形状不变，`title` 改为取推送标题。
- **Web**：`PushView` 解码加上 `title`；`PushBell` 按上面的布局显示，横幅改为显示标题；「去会话里问」的引用标签用标题，不再截正文首行。

## 删除

- 系统通知标题使用会话标题、没有标题时退回「micnext」的规则。
- 系统通知正文末尾的「附 N 个文件」。文件在通知中心和会话里可以看到。

## 不做

- 主屏幕图标显示未读数（角标）。需要的话以后单独做。
- 去掉 Markdown 符号：已经在工具说明里要求纯文本，不做转换。
- 副标题、操作按钮、通知分组：iPhone 的网页推送不支持。

## 验收

- 本地：`cargo fmt`、`cargo clippy -- -D warnings`、`bun run check`、转换脚本测试。
  - 用例覆盖：IM 消息的文字是「标题、空一行、正文」；转换脚本给旧推送补标题。
- human：让 agent `push` 一条，检查 iPhone 锁屏、通知中心和微信里的标题与正文；再看一次定时任务结果推送的标题。
