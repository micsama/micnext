# B1：长期记忆

日期：2026-11-16。状态：讨论中，先不实现。

## 1. 要解决什么

模型每次开新会话都从零开始。你说过的偏好、纠正过的做法、服务器和账号这类环境事实，只活在当时那个会话里：

- **新会话**：要重新说一遍，或者等模型再踩一次坑。
- **长会话**：微信和定时任务这类会话靠压缩维持，这些事实只能寄托在摘要里，压缩几次后容易丢。

现在唯一跨会话的是设置里的「用户偏好」（`general_prompt`）。它会进每次请求的 system prompt，但只有你手写才会变，模型学到的东西进不去。

## 2. 和现有机制的分工

| 机制 | 内容 | 谁写 | 何时进上下文 |
|---|---|---|---|
| 用户偏好 | 你对模型的长期要求 | 你，在设置里 | 每次请求 |
| skill | 怎么做某件事，基本稳定 | 你或模型，写文件 | 匹配时加载 |
| 专题（[B2 待批准](../blueprints/topics.md)） | 某个主题积累的结论和数据，持续增长 | 模型 | 聊到这个主题时打开 |
| 压缩摘要 | 本会话到目前为止的进展 | 压缩 | 本会话 |
| **长期记忆** | 跨话题都适用的少量事实：你是谁、偏好什么、环境是什么样、纠正过模型什么 | 模型为主，你可以改 | 每次请求 |

划界规则：只对某个主题有用的结论写进专题；**换个话题也仍然该知道的**才进记忆。所以记忆应该很小、常驻，不需要检索。路线图里提到的「项目决定」，多数属于专题。

## 3. 候选

### 3.1 存在哪、和用户偏好什么关系

| 候选 | 做法 | 取舍 |
|---|---|---|
| **甲** | 把「用户偏好」升级为记忆：同一段文字，你在设置里改，模型用工具改 | 只有一个来源，你在一处就能看到模型记住了什么。代价是模型可能改动你手写的内容，靠工具只能按条增删改、改动在对话里可见来约束 |
| 乙 | 用户偏好保持你专用，另加一段模型维护的记忆，两段都常驻 | 作者分得清，你写的内容不会被模型碰。代价是同一类事实有两处可放，模型和你都要判断写哪里 |
| 丙 | `<data_dir>/MEMORY.md`，模型用现有文件工具改，不加新工具 | 实现最省。但写入看不出是在「记忆」，体积上限没处拦，也和存在 SQLite 里的用户偏好分成两处 |
| 丁 | 一个目录，每条记忆一个文件，常驻的只有索引，正文按需读取 | 能容纳大量记忆，但形态和专题几乎一样。真到这个量级，说明内容该进专题 |

倾向**甲**。理由是「同一事实一个来源」，而且你本来就是从设置里看用户偏好的。如果你很在意手写的部分不被模型改，就选乙。

### 3.2 谁来写、何时写

| 候选 | 做法 | 取舍 |
|---|---|---|
| **a** | 新增 `memory` 工具，按条新增、替换、删除。你说「记住」时写；你纠正它或透露长期偏好时，模型主动写 | 成本最低，写入在对话里显示为工具行，可以当场让它撤回。漏记还是多记取决于模型，靠工具描述调 |
| b | 每次写都要你点确认（复用 `ask_user`） | 不会误写，但打断对话。单用户场景下，事后可见、能撤回已经够用 |
| c | 杂活模型在 run 结束或压缩时，自动从对话里提炼记忆 | 不依赖主模型记得去写，但每次多一次调用，还容易记进一次性的内容。等 a 用一段时间、确认漏记严重再考虑 |

倾向 **a**。工具的形态参照现有的文件编辑工具，用旧文本定位替换，不整段重写，避免模型顺手覆盖别的条目。

### 3.3 进上下文的方式

- **位置**：放在 persona 块末尾，也就是现在「用户偏好」所在的位置。子 agent 和定时任务都带上，和现在的用户偏好一致。
- **缓存**：记忆一改，所有会话下一次请求的前缀从这里起都变了，会各有一次缓存未命中。记忆很少改，可以接受。

  另一个做法是每个会话冻结一份快照，到压缩时再刷新。好处是不破坏缓存，但要存快照或版本，违背「配置不单独版本化」，而且写入的那个会话本来就从工具行里知道了这条记忆。所以不冻结。
- **上限**：设一个硬上限，超出时工具报错，要求模型先合并或删掉旧条目。具体数值在 B2 定，放进 `limits.rs`。上限是让记忆保持精炼的主要手段，比描述里写「请简洁」可靠。

## 4. 定方向时一并考虑的影响

- **和设置保存的冲突**：设置页保存时会提交整组偏好。如果模型刚写完记忆，而你打开着的设置页是旧的，保存其他项时会把记忆覆盖回旧值。所以无论选甲还是乙，记忆都要有自己的读写接口，不跟其他偏好一起整组保存。
- **可见性**：模型写入时，对话里显示工具行。设置里能看到全文，并且可以直接改。不另建记忆页。
- **注入风险**：模型读到的网页或文件可能诱导它写入一条记忆，而且会长期生效。单用户场景下，靠写入可见、可撤回兜底，不做来源隔离。这是一个取舍，不是已经解决的问题。
- **备份**：记忆随设置备份导出。它和用户偏好是同一类东西。

## 5. 不做

- **向量检索**：常驻的小记忆不需要检索，大量知识归专题管。
- **自动提炼**：见 3.2 c，等实际漏记再说。
- **按人设分记忆**：记忆说的是你和你的环境，与人设无关。
- **跨会话搜索聊天记录**：这是另一个能力（模型按需查过去的对话），与常驻记忆互补，需要时另起 B1。

## 6. 需要你定

1. 选甲（用户偏好升级为记忆）还是乙（两段分开）？
2. 选 a（模型主动写，事后可见）还是 b（每次确认）？
3. 上限大约多大？参考：现在的 skill 描述上限是 1024 字。常驻记忆我倾向 2000 字左右。
