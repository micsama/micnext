# B1：会话自动标题与重新生成

**状态（2026-10-13）：[思考选择 B2](../blueprints/archive/reasoning-selection.md) 已验收 CLOSED；[标题 B2](../blueprints/archive/session-title.md) 进入独立评审，待批准，尚未实施。human 已确认侧栏刷新边界及标题只 trim、依赖提示词约束的规则。独立的「回到底部」按钮尺寸调整已实施。**

## 一、诉求与现状

用户希望首个问题发送后自动给 session 取标题，优先使用便宜、简单、无思考的模型；考虑 DeepSeek-v4-flash，也接受默认模型。聊天页标题旁需要一键重新生成。没有专用模型配置时的行为须明确。

- `mic-store/src/store.rs` 的会话摘要从首条 UserInput 的文本取 `preview`，不是模型生成的标题；只发图时可以没有文本预览。
- `ChatView.svelte` 用 `preview` 显示页头和浏览器标题；侧栏也消费会话摘要。打开会话的 `info` 目前只在首次读取，不会因后台标题变化自行更新。
- 模型是 SQLite 中的条目，全局默认与会话选择已分开；用户调项经 Web 保存，不放 `config.toml`。
- 本地 Provider 已支持按会话选择 DeepSeek 的 `reasoning_effort: none`。`ModelRequest` 不增加覆盖字段；思考选择在本轮 Provider 创建时读定，静态输出限制仍归模型条目。这里不判断上游模型当前是否可用，实际使用须以服务商模型列表和连接验收为准。
- 模型条目在同一服务商下按模型名唯一。原先把思考强度存进模型条目是参数归属问题，不能据此限制新需求；本次将其移到用途的调用选择上，同一个模型可被会话和标题用途选择不同档位。

## 二、模型选择候选

| 候选 | 行为 | 取舍 |
|---|---|---|
| A：只用全局默认模型 | 取标题时读当时全局默认，沿用该条目的参数 | 改动最少，无专用配置；默认模型贵或开启思考时，标题调用也如此 |
| B：标题模型可选，思考强度按用途选择（human 修正后的方案） | 设置页增加标题用途配置：模型选择 + 节点滑条；复用模型目录与 GET 返回档位；未指定模型时用全局默认 | 同一模型可以聊天有思考、取标题无思考；不重复建模型、不写死供应商或模型名 |
| C：自动找 DeepSeek-v4-flash，找不到用默认 | 按名字/供应商猜专用模型，再隐式替换 | 不推荐：模型名不表达价格或用途，配置缺失与调用失败容易混为 fallback，还可能意外换服务商 |

B 的「使用默认模型」是用户可见的选择模式，不是专用模型出错后的降级。默认模式只允许档位为空；需要固定 none 时选具体模型。明确指定的模型被删除、凭据无效或上游失败时，显示标题生成错误，要求重选或重试；不自动改用默认。全局没有默认模型时也明确提示。

2026-10-13 human 明确：设置模型的配置阶段不设置思考强度；对话时用带节点的滑条选择，滑条与设置接口 GET 返回的档位挂钩。标题用途配置复用同一交互。原先建议沿用模型条目推理参数的方案撤回；Provider 建实例时接收本次用途选定的参数。

## 三、推荐用户行为（未批准）

- 常驻模式的 Root 会话首次出现含文字的 UserInput 后，后台自动生成一次，不等待正文回答；core 统一承载，Web 展示标题。不为子任务会话自动命名，`-p` 不触发自动标题。
- 自动生成只用首条问题的文本，限制输入长度，不发送工具结果、完整历史或图片原件。只有图片无文本时暂不自动调用，保留会话编号/既有预览显示；之后首次有文字的问题可触发。命令不算问题。
- 输出简短标题，跟随问题语言，不含解释；标题是独立的会话元数据，不写成 Reply，不进入聊天上下文，也不改变最近消息活动时间与侧栏排序。
- 未生成时继续展示首条消息预览或会话编号。这是固定的未命名显示规则；失败时另显示错误，不能用预览掩盖失败。
- 标题旁增加「重新生成标题」按钮，生成中显示忙状态且禁止重复点击。手动生成根据最近一小段用户文字问题概括当前主题，输入长度有固定上限；不发送完整历史和工具结果。旧会话也可点击。
- 重新生成只保证重新调用，不保证模型一定返回不同措辞。成功才替换旧标题；失败保留旧标题并显示错误。
- 自动/手动走同一生成流程，同会话同时只有一个标题调用；正文回答与标题调用独立。失败不妨碍继续聊天；标题错误有可见状态和手动重试入口。
- 已有会话不批量补生成；当前页头、浏览器标题与侧栏对应条目同步。未打开会话按约定列表刷新时机更新，推荐不加全局事件流；规则随标题 B2 审批。

## 四、进入 B2 时必须明确的契约

思考选择独立在 `docs/blueprints/archive/reasoning-selection.md`，标题生成在 `docs/blueprints/archive/session-title.md`，分别批准、实施与验收。评审后明确的精简：

1. 生成中只放 core 内存，库只存标题/错误；运行时持有独立标题 JoinSet，不改正文调度，不做启动生成状态收尾。
2. 新消息 id 等于第一条含文字 UserInput id 且尚无标题时自动生成，不存自动资格或补跑旧消息。
3. 旧模型档位删字段，会话/run 新列为空，不搬迁档位；调用用途旧值也不回填。
4. 保留会话 SSE；标题变更作为失效通知，客户端顺序重读标题 GET，避开旧事件覆盖新快照，不加发布锁切点。
5. human 已确定只 trim，再检查单行/非空/40 字上限与正常 EndTurn；提示词要求纯文本，不剥格式、不截断。重读现有会话详情获取标题及内存生成状态，不另建标题 GET。
