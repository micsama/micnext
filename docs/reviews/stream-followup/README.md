# 流恢复周边复查

日期：2026-11-05。范围：草稿恢复后的会话流、共享 SSE 客户端与相邻刷新路径；不是全仓库审计。

## 已处理：重连遗留取消监听器

`web/src/api/sse.ts` 每次建立流向长期存活的 AbortSignal 注册一次监听；网络断开或事件解析失败后只关闭 EventSource，没有注销监听。`once` 只在真正取消时移除监听，不能处理常规重连。全局流在登录期间、会话流在打开期间持续累积监听。

已在 finally 中注销本次监听，不改变公开契约。使用 Bun 转译实际源码、替换取票函数及 EventSource 模拟网络断开：修复前 20 次连接结束后剩余 20 个 abort 监听，修复后为 0，20 个 EventSource 均关闭。此为客户端生命周期验证，不是浏览器网络验收。

## 待定 P2：模型重试等待状态不能随重连恢复

触发：模型调用失败后进入重试等待，此时切走再回来或网络重连。

证据：`crates/mic-gateway/src/stream.rs` 的 Ready 只有草稿等快照，没有当前重试次数和等待截止时间；`web/src/state/session.svelte.ts` 只在收到 model_retry 增量时建立倒计时，断流 finally 清空 modelRetry。已经发生的重试事件不会回放。

影响：重连后直到下一次重试事件前，当前重试次数和倒计时不可见；调用仍正常执行，不影响草稿正文完整性。现有 `model-retry-indicator` 的真实链路验收应补这个场景。

候选：明确当前调用尝试的重试等待状态由谁拥有，并与 ready 快照、增量及等待结束一起定义。涉及 core/HTTP 公开契约，需 B2 批准后实现；本次未扩大草稿蓝图范围或修改协议。
