# B2：聊天图片改为缩略图 + 浏览器原生加载与缓存

状态：已实现，待 human 验收（2026-11-13）。

## 问题

- **下载过大**：聊天里图片最高显示 256px（`max-h-64`），却下载原图；规整上线前的旧图最大约 1MB。服务器出口约 465KB/s，一张图能占满连接约 2 秒，排在后面的请求跟着卡（见 [session-load-diagnostics](session-load-diagnostics.md) 中 54 的记录）。
- **不复用**：图片接口是 `no-store`，每次进会话都要整张重下。
- **前端自造轮子**：`HistoryImage` 用 `fetch` 取 Blob 再生成 object URL，为此手写了引用计数、5 分钟闲置回收、请求中止和 IntersectionObserver 懒加载。这些本来是浏览器加载 `<img>` 自带的能力；之所以要手写，只是因为图片走了 `fetch`。

## 参照

网页版 LLM 聊天产品的常见做法是：上传时或请求时生成多档尺寸，列表里用小图，点开才看大图；页面直接用 `<img src>` 引用图片 URL，由浏览器负责懒加载、去重和 HTTP 缓存；鉴权靠同源 cookie 或短时签名 URL。micnext 是同源 cookie 登录，`<img>` 请求会自动带上 cookie，可以直接照搬。

## 做法

- **缩略图在请求时生成，不入库**：从原图缩出，不加存储也不用迁移，旧图同样受益。只有一个用户，生成的 CPU 开销不成问题。
- **缩略图规则**：等比缩小到宽 ≤ 1024、高 ≤ 768，按 3 倍屏也够 256px 的显示高度。只有原图已经在这个尺寸范围内、**且**不超过 `THUMB_KEEP_BYTES`（200KB）时才原样返回，否则一律重新编码：有实际透明像素的编码为 PNG，其余编码为 JPEG（质量 80），透明判断与入库规整一致。200KB 是原样返回的门槛，不是输出上限，透明 PNG 重新编码后仍可能更大，以 51 旧图的实测结果为准。
- **原图只在点开放大时加载**。
- **前端回归原生 `<img>`**：消息里的图片写成 `<img src=".../thumb" loading="lazy" decoding="async">`，放大预览用原图 URL。删掉 `HistoryImage` 里手写的 Blob 缓存、引用计数、闲置计时和中止逻辑，加载失败用 `onerror` 显示占位。浏览器不保证卸载时立即取消下载，是否还卡以慢网实测为准。
- **缓存用协商，不用长期免检**：两个图片接口都返回 `Cache-Control: private, no-cache` 和 `ETag`。ETag 标识响应内容：原图按图片 id 生成；缩略图另含缩放规则（尺寸上限、质量、原样门槛），规则改了 ETag 随之变化，客户端不会一直留着旧缩略图。浏览器复用缓存前带 `If-None-Match` 来问，服务端先过登录和归属检查再回 304，不生成缩略图。每张图仍有一次小往返，换来后续请求始终要过鉴权；它不擦除磁盘缓存，也不撤下已显示的图片。

## 契约变更

- **mic-media**：新增 `pub fn thumbnail(image: &ImageData) -> Result<ImageData, MediaError>` 和标识规则的 `pub fn thumbnail_rule() -> String`，与 `normalize` 共用内部的 `encode`。
- **mic-core**：新增 `Kernel::thumbnail(ImageData)`，在 `spawn_blocking` 里生成；失败为 `KernelError::Thumbnail`，返回 500。
- **Gateway**：
  - 新增 `GET /api/sessions/{id}/images/{image_id}/thumb`，归属检查和 404 语义与原图接口相同。
  - 两个图片接口改用上面的缓存头并支持 304。
- **Web**：
  - `HistoryImage` 改为纯展示组件 `ChatImage`（参数为图片地址），消息、Trace 和文件附件里的图片共用它。
  - `fetchImage` 删除。

## 不做

- 不在服务端缓存缩略图，也不预先生成。
- 不改发给模型的图片：模型仍拿规整后的原图。
- 不改文件接口：文件在磁盘上可能被改写，仍保持 `no-store`。
- 不存图片宽高：存宽高能让加载前的占位尺寸准确，但要改 schema 并写迁移脚本，眼下的占位块够用。

## 实测（2026-11-13，生产库副本，debug 构建）

会话 51 的 8 张旧 PNG 原图共约 3.7MB，生成缩略图后共约 730KB：

- 6 张不透明的图从 175–395KB 降到 21–66KB（JPEG）。
- 2 张透明 PNG（原图 1035KB 和 917KB）降到 226KB 和 211KB。这两张仍是 PNG，大小超过 200KB 的原样门槛，但只有原图的四分之一不到。

另外用 curl 验证了以下行为：

- 带 `If-None-Match` 请求时返回 304。
- 不带 cookie 时返回 401。
- 图片 id 不属于该会话时返回 404。
