# B2：缓存冷了以后整理历史

状态：已批准（2026-10-28），实现完成，待验收。

来源：[B1](../brainstorm/skills.md) 第三节。有效期的实测数据见 B1。

## 行为

- **目标**：在适用范围内省上下文，不追求准确识别缓存状态。闲置阈值取经验值并放宽，宁可晚整理。
- **什么时候整理**：只在普通对话 run（含定时任务触发）开始时、第一次调用模型之前判断；`/clear`、`/compact`、撤销这类指令 run 不触发，免得新增边界挡住用户要撤销的那条。看这个会话上一次对话调用到现在隔了多久，不论当前边界；超过即将调用的模型的闲置阈值就整理。阈值是 `limits.rs` 里的经验值，按模型名前缀匹配：
  - `gpt-`：3 小时
  - 其他模型：24 小时

  没超过时，历史照旧只追加，不做任何改动。
- **冷了以后做什么**：二选一，每次 run 至多一次。
  - **提前压缩**：当前窗口里最近一次调用的占用超过 50%（清空或撤销后可能没有，按轻整理处理），直接走完整压缩，流程、通知和失败处理都和到 80% 时的自动压缩相同。
  - **轻整理**：其余情况不调用模型，只把整理点之前的旧内容换成占位，然后照常运行。没有可换的内容就什么也不写。
- **轻整理换掉什么**：当前窗口内、这次 run 的输入之前的消息。
  - 超过 `ELIDE_TOOL_TOKENS` 的工具输出，规则和压缩保留段相同。
  - skill 正文，包括 `skill` 工具的结果和 `/name` 注入的正文，不论长短。占位文字是「已加载过 skill X，需要时重新调用」。

  只换上面两类，用户消息里的文字和图片原样保留，工具调用和结果的配对也保持不变。图片暂不省略：它不能像 skill 一样重新加载。
- **整理点是事实**：轻整理写一条新的边界，和一条通知放在同一事务里提交。通知文字类似「长时间未活动，已整理历史：省略 3 条工具输出、1 个 skill 正文」。之后的每次请求都按这条边界渲染，前缀从这次起重新稳定下来。
- **撤销与清空**：轻整理和压缩一样可以撤销，撤销后恢复原文。`/clear` 之后，之前的整理不再起作用。之后再压缩时，已经换成占位的内容继续保持占位。
- **定时任务并入**：去掉定时任务到点时「占用超过 50% 先插 `/compact`」的专门规则，由这条通用规则覆盖。间隔超过阈值的任务照样提前压缩；间隔短的任务按普通自动压缩阈值处理。
- **压缩保留段同步**：压缩时保留段也用同一套规则处理 skill 正文，最新一步除外。这样「哪些旧内容可以换成占位」只有一处规则。
- **暂不做**：
  - 探测缓存是否真的失效（观察 `cache_read_tokens`）。
  - 省略图片。
  - 切换模型时当作冷处理。
  - 把阈值做成模型设置项。

## 契约

- **mic-message**
  - 新增 `ContextBoundary::Trim(Trim { base: Option<MessageId>, elided: Vec<MessageId> })`。它不移动窗口起点，也不带摘要；`base` 是整理时的有效边界，窗口沿它解析，不复制摘要。
  - `Message::elide_output` 扩展到用户输入里的 `Skill` 片段和 `skill` 工具结果，其余片段不动。占位文字改成不提摘要的通用说法，压缩和轻整理共用。
- **mic-store**
  - 窗口解析：从最新的有效边界沿 `Trim::base` 往回找，找到第一条压缩或清空边界作为窗口起点。`ContextWindow` 新增 `elided`（解析后的占位并集）。占位集合是这条边界的 `elided` 加上这些 `Trim` 的 `elided`。压缩时带过去的占位（`carried`）也取这个并集。实时请求和 Trace 历史视图共用这一处解析。
  - 新增 `commit_trim(session, elided, notice)`，在同一事务里写边界和通知。
  - 撤销：`RevokeCompaction` 同时适用于 `Trim` 边界，不改名。`ContextView.compactions` 改为 `revocable: Vec<RevocableView { boundary_id, state }>`，不再附带压缩内容。
  - 新增按会话取最近一次对话调用结束时间的查询，不受边界限制；`context_usage` 口径不变。
  - `fire_schedule` 去掉 `compact` 参数，`FireResult::Fired` 只带 Trigger 一条消息。
- **mic-core**
  - `limits.rs`：新增 `IDLE_TRIM_AFTER`（按模型名前缀匹配的闲置阈值表，带缺省值）和 `IDLE_COMPACT_PERCENT = 50`，删除 `SCHEDULE_COMPACT_PERCENT`。
  - `compaction.rs`：占位挑选抽成 `elidable`，压缩保留段和轻整理共用；`tidy_if_idle` 在普通对话 run 主循环前调用。
- **Web**
  - `types.ts` 解码 `trim` 边界。
  - 消息流里的整理边界显示为分隔条，带「撤回」按钮（`TrimBoundaryView`）。
  - Trace 的上下文视图把整理点当作一种边界来显示。

## 验收

- 自动：
  - 写一个模块测试。构造一个含大工具输出和 skill 正文的会话，把上次调用时间设到阈值之前。检查第一次请求里这些内容已换成占位、窗口里有 `Trim` 边界；第二次请求的前缀与第一次相同；连续两次 Trim 后占位累加；撤销、再压缩、清空后窗口正确。
  - 定时任务的现有测试随规则调整一并更新。
- 人工：
  - 隔天回到微信或 Web 会话，看通知文字和 Trace 里的请求。
  - 用 SQL 观察整理后那次调用和下一次调用的 `cache_read_tokens`。
