# B2：Web 微信设置切换会话模型

**状态：待批准（2026-10-12）。**

## 一、范围与用户行为

在 Web「设置 → 微信」的已绑定账号区域增加「会话模型」选择器，修改该账号当前绑定的已有会话。模型复用「服务商与模型」中的活动条目，以服务商分组，保存模型 ID；不另建微信模型配置。

- 未绑定账号时不显示选择器；已绑定但需要重新登录或连接异常时仍可切换。
- 读取绑定账号的 `session_id`，通过现有会话查询获取 `model_id`。
- 选中条目立即保存，成功后显示已保存的模型；失败保留原选择并显示原因。
- 会话 `model_id` 为空时显示当前全局默认，提示尚未固定、下一轮取默认；切换后固定选择。
- 已选模型被删除时显示「原模型已删除，请重新选择」；没有活动模型时提示先到「服务商与模型」添加。
- 执行中切换沿用 409，提示本轮结束后再切换；成功切换用于后续轮次，不修改历史与上下文。
- 改全局默认不覆盖已有会话选择；同号重新登录沿用原会话及其选择。

`/model` 后续另定，本次不新增斜杠命令。

## 二、公开契约与调用方影响

修订现有 `PUT /sessions/{id}/model`：允许 Web Root 和微信 Root 会话调用；其他渠道与非 Root 会话仍返回既有 ReadOnly。请求仍为 `{ "model_id": number }`，成功仍为 204；不存在、模型已删除、执行中等错误沿用现有规则。

这只扩大模型设置接口的适用会话范围。`SessionItem.writable` 仍表示能否从 Web 发消息，微信会话仍为 false。发消息接口、人设设置接口的权限规则不变。

复用 `GET /channels/wechat` 的绑定信息、`GET /sessions/{id}` 的模型 ID、现有模型列表及默认 ID。无需扩展微信状态 DTO、core/store 公开签名或数据库结构，无新增依赖。

前端消费者为 `WechatSection.svelte`：复用 `ModelPicker` 与 `settingsStore`，在既有微信状态刷新中读取绑定会话，避免旧账号/旧请求结果覆盖当前显示；保存期间禁用重复切换，保存后重新读取服务端状态。
