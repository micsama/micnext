# B1：运行中停止

**状态：方向已定（2026-10-15 human），进入 [B2](../blueprints/archive/run-stop.md)。**

## 问题

模型卡住、跑偏或工具跑太久时，页面和微信都停不下来：只能等挂起判定、轮次上限或工具超时。插嘴（新消息在模型/工具边界并入）只能改方向，不能叫停正在进行的调用。

## 已定

| 问题 | 决定 | 理由 |
|---|---|---|
| 停什么 | 停当前这一轮（run）：正在进行的模型流、工具批、重试等待、压缩调用都立即中止 | 用户感知的单位就是「这轮回答」 |
| 半截回复 | 保留已输出的正文，作为历史给模型看，紧随一条「已停止」通知；trace 中该次调用记为「用户停止」 | 用户已看到的内容不消失；模型知道自己说到哪被停 |
| 正在跑的工具 | 中止并记为「已取消」，结果写明被用户停止、副作用未知；shell 整组杀进程 | 复用现有已取消结果与 shell 的丢弃即杀 |
| 排队消息 | 已发出但未被本轮并入的消息照常开新一轮；已并入的属于被停的这轮 | 停止只撤回执行，不撤回用户说过的话；「停下再说」= 停止 + 发送 |
| 入口 | Web 停止按钮（按 run 绑定）、Web 与微信的 `/stop` 指令（停当前） | 一个内核方法，两个 Channel 共用 |
| 终态 | 新增 run 状态「用户停止」，与进程退出导致的 `interrupted` 区分 | 看板、trace 能区分主动停止与异常中断 |

## 不做

- 停止不撤销已发生的副作用，不回滚文件。
- 不做「暂停/继续」：停了就结束本轮，继续靠发消息。
- 异步任务、子 agent 的停止随异步方向另议（[路线图 §2.4](product-roadmap.md#24-消息任务与取消)）。

本决定修订路线图 §2.4「同步 shell 执行中不承诺即时停止，不为此增设强制杀进程与取消落盘」：用户主动停止时立即杀进程并落盘取消结果。
