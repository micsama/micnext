# B1：轻量 trace 与看板

**状态：方向已拍板（2026-10-14），合并 B2 见 [run-trace](../blueprints/run-trace.md)，未实施。** 关联：[SQLite 整理 B1](sqlite-organization.md)、[error-logging B2](../blueprints/error-logging.md)。过程稿已收敛，本文只留结论。

## 目标与范围

轻量版 Langfuse：按 run 看已结束的 trace（耗时、用量、层级/先后/并行、输入输出、metadata），加简单看板。数据量不大，继续用 SQLite。

- trace 只看结果：不展示执行中的 run，不设 running 状态，不每个增量写库。
- 复用业务执行事实，不另建 trace/span 表；logs 独立库，按 session/run 关联排查。
- 不做历史配置查看、原样重放、外部导出。
- 旧数据直接清理，按新 schema 重建，不迁移、不兼容。

## 已拍板

| 问题 | 结论 |
|---|---|
| 模型调用记录 | 调用行是主事实：trace 以调用行为准，Reply/Boundary 是可选关联（连续失败、首请求被拒、压缩失败都只有调用行），不从回复反推调用。谁执行谁记录：模型调用模块在请求组装完成时确定输入描述，流结束时捕获时间、首次输出、用量、StopReason，写调用事实；普通对话、压缩、标题同一规则。后处理（解析、应用）另行负责，失败由现有通知表达，不改写调用成败。成功压缩时调用与 Boundary 同事务，但数据各自来自调用过程与压缩结果。崩溃中的尝试无记录，显示 run 在最后一条事实后中断 |
| 工具 | 不建表。工具结果是消息（输入的特化），由执行该工具的并行任务自己落盘：调用前后取真实起止，ToolResult 带 `started_at`，消息 `created_at` 取工具返回时刻；消息 id 只表示落盘顺序，trace 按执行时间展示。父调用 = run 内消息顺序上最近的 Reply。恢复补的 `Cancelled` 只在恢复产生，展示为“中断，结果未知”，无时长 |
| 重试 | 不加列。重试复用同一请求与 context：同 run 内连续、purpose/boundary/through 相同的调用即一次逻辑调用的多次尝试 |
| 模型身份 | 调用行记录 `model_id`（可空外键）、模型名、思考档位；run 不再存配置副本，`context_window` 改从调用行取模型 |
| 压缩 | 调用归属 run；成功时 Boundary 写入 `model_call_id` 关联调用（现 `commit_compaction` 未写，需改） |
| 标题 | 会话级调用，只留状态、用量、耗时；输入与产出不保留历史 |
| 日志 | 按 run（标题按会话）关联；旧库报错时一并列出日志库路径，由用户与业务库一起删除，避免复用的 session/run id 串到旧日志 |
| 页面 | 直接做 Web trace 列表、详情、看板；不建 SQL 视图 |
| 时间 | 只存 Unix 毫秒，时长相减；中断不显示时长；缺失显示未知 |
| 统计口径 | 轮次含该 run 全部调用（含压缩、失败尝试）；会话另含标题调用。步数与尝试次数分开计。用量缺失不当零，显示已知合计 + 未知 N 次 |
| 价格 | 模型设置里填单价（输入、缓存命中、输出），存模型配置；费用按当前单价估算并注明，没填显示未知 |

## 输入重建

调用行记录输入描述：边界、起点、终点、被排除的输入、挪到末尾的输入。普通对话记边界、终点和本步待处理输入（`request::build` 后会挪到末尾）；压缩额外记实际起点（预算裁掉的前段之后）和排除的本步待处理输入。重建统一为：按边界读窗口 → 截取起点–终点 → 去掉排除项 → 走该用途的同一组装（`request::build`、压缩指令）→ 把末尾项挪到末尾，成功与失败一视同仁。不借 Boundary 等业务结果反推。

压缩指令的附加文字不另存：手动 `/compact` 取本 run 的 Command 消息，自动压缩取被排除的待处理输入的文字，都已在库中。

调用时被过滤的未认领且非 held 输入记为排除项，重建不靠后来的认领结果推断（见 B2）。

只展示消息部分，system 与工具定义不展示。页面称“按当前规则重建的输入”，不称原始请求；组装代码变化带来的偏差接受，不存请求快照。崩溃中的工具与模型调用无终态，显示未知。

## 采集改造

| 项 | 改造 |
|---|---|
| 工具结果 | `run_tools` 每个任务包围查找/调用并自行写结果与发布事件；收取循环只处理 panic 与写库错误 |
| 首次输出 | Provider 解析边界取首个非空正文/推理/工具参数增量；ModelEvent 需暴露工具参数增量的首次时点 |
| 模型结束 | 观察到 Finished/Err 时取，早于等待 publisher（普通对话 `record` 当前在其后取）和压缩的解析、读文件 |
| 用量 | 调用成败与已收到的 usage 独立记录。Provider 契约要改：流失败时也交出已收到的 usage、首次输出与结束时刻（现只有 `Finished` 带 usage，报错只剩 `ProviderError`）；写入路径不再因失败置空 |
| 输入描述 | 组装完成时由调用方给出；压缩在预算裁剪、排除待处理输入之后取 |
| StopReason | 存成列；失败分类先不存，错误文本够用 |
| `context_window` | 选用量依据限定普通对话用途，避免压缩归属 run 后选中压缩用量；看板总量仍含压缩和标题 |

## 展示

原型：`tmp/trace-preview/index.html`（模拟数据，只定交互与信息取舍，不进 git）。正式页面在 `web/` 新写 trace 组件；复用现有主题变量、Markdown、Icon、CopyButton、工具结果格式化与 API 设施。`ReplyView`、`ContextBoundaryView` 带聊天操作，不原样嵌入，出现第二个消费者再抽只读部分。选中态、间距吸收进共享主题，不顺带重写聊天页。

本轮验收：

- **布局**：左栏会话列表；中栏按会话连续显示：顶部冻结系统提示（会话级，显示当前配置），然后是压缩边界、轮次（可折叠）→ 用户 / AI / 工具，更早的轮次向上按完整 run 分页加载；右栏详情，页签为概览 / 预览 / 输入，输入点开才重建。
- **信息克制**：每层只写自己的事实。子项的问题由关联行图标 + hover 承载，不在父级重复；快慢只用颜色表达。
- **调用行**：AI 行来自调用行。没有 Reply 的调用（重试全失败、首请求被拒、压缩失败）同样成行，显示错误与尝试。
- **耗时**：一步 = 一次模型调用（含失败尝试）+ 它发起的并行工具批，时间条以步为全长，按真实时间戳定位：模型数字写各尝试耗时之和，重试等待与模型结束到工具启动的间隙归“其他”。工具终点未知则整步长度未知，不把已知部分画满；各行只写自己的耗时。轮次拆成模型 / 工具 / 其他。
- **标记**：没发起工具的 AI 带回复图标，但不推断它是否为本轮最后一次。插队输入由 `absorb` 并入同轮，按顺序显示。
- **推送**：本轮不做。trace 聚焦 agent 执行，Channel 投递细节不纳入。
- **选中**：hover 底色 + 1px 边框 + 1px 光晕。Shift 连选轮次，右栏给加总。
- **日志**：新增按 run 查询（现有历史接口只返回最近一批），过滤 WARN/ERROR，可复制；不带 run 的 INFO 看不到。
- **用量与着色**：按 `Usage` 口径（输入含缓存命中），口径见[统计](#已拍板)。同类耗时着色用后端给的中位数：模型按用途 + 模型分样本（对话、压缩、标题不混），工具按工具名；只取成功样本，hover 写样本数。
- **看板**：按天的 run 数与成功率、调用数与失败率、token（含缓存）、费用（按当前单价）、平均耗时，按模型、工具分组。并行工具耗时不累加成墙钟，缺失用量不当零。
- **正式实现**：选中只更新局部；页签按需请求；聚合不读正文和图片；`run_id` 等索引随读取路径加。

原型里的子 agent、定时任务部分只作下节参考，不在本轮验收。

## 未来：子 agent 与定时任务（不在本轮）

关系已有事实承载：`parent_session_id`；`Task` 带 `parent_tool_call_id`；`Triggered` 带 `module` + `ref_id`；回注输入 `Completion`。trace 只展示这些关系，不加新机制。

- **子 agent**：父会话里是一个工具行（bot 图标），耗时写工具自身时长；同步即子会话墙钟，异步只到派出。不在父中栏展开子会话；点工具行右栏给子会话摘要与跳转。左栏子会话挂父会话下，多了默认折叠。子会话首条输入反链到发起的工具调用。异步完成在父会话后续轮次出现一条完成输入，与插队同规则并入或开新轮，关联回工具调用与子会话。
- **token**：轮次与会话统计只算自身模型调用，不卷入子会话（异步消耗晚于父轮次结束，卷入会让已结束的数字事后变化）。子 agent 工具行的 token 列填子会话总量（灰色，hover 注明不计入本轮）；会话层另给「含子会话」合计，按 `parent_session_id` 汇总。
- **定时任务**：与会话分开，左栏会话分组下方单独一个「定时任务」区。任务是多次运行的集合，不是会话：点任务，中栏列运行（时间、状态、耗时、token、是否推送），右栏放任务本身（规则、来源会话、创建它的工具调用、运行与报错/中断次数、耗时中位、推送次数）。点某次运行进入对应 `Triggered` 会话，顶部面包屑「任务 › 运行时间」可返回；该运行临时挂在左栏任务下，离开即收起，其余运行不进左栏。
- **trace 只看不管**：运行列表只带简单筛选（只看异常、模糊匹配、↑↓ 与回车）。暂停、立即运行、改指令/规则等管理功能放未来独立的定时任务管理页，那里点某次运行跳回 trace。日常改动也可直接对 agent 说。
- **不做**：任务修改历史（业务配置不版本化），只记由哪次工具调用创建。
- **缺的事实**：任务表记创建它的工具调用；`Completion` 关联子会话与工具调用；按父会话汇总子会话用量的查询。
