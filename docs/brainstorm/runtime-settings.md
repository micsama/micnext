# 运行期设置：配置边界与后续想法（2026-10-08）

状态：B1 已收敛并落地（阶段一 CLOSED），决定与契约见 [`blueprints/runtime-settings.md`](../blueprints/runtime-settings.md)。
本文只留配置边界的取舍依据和未定的后续想法。

核心划分：**设置页管长期偏好，会话保存下一轮选择，run 保存当轮事实。** 「下一轮想用什么」和「上一轮实际用了什么」
是两件事，不是重复真相；从 run 反推会让切换未发送、插话、失败、刷新都需要特殊规则。

## 一、配置边界

`config.toml` 只放**启动必需、或不能让网页改的**；其余用户可调项进 SQLite，经 Web 设置页修改，下一轮 run 生效。

| 项 | 去向 | 理由 |
|---|---|---|
| `core.data_dir` | 留 | 找到库之前就要知道 |
| `gateway.listen`、`gateway.token` | 留 | 网页起来之前就要知道；能从网页改等于能自己改门锁 |
| `core.owner` | 留 | 消息归属身份，不是昵称；改它会切断历史归属 |
| `core.max_turns`、`gateway.workdir` | 已入库 | Agent 行为参数；「新会话默认工作目录」改了不搬已有会话 |
| `[models]` | 阶段二入库 | 见 blueprint §四 |

## 二、微信的选择

已定微信单人自用、单会话（`/clear` 只清上下文），「渠道默认」与「该会话选择」是同一件事，只存一份：Web 设置页的微信区域。
具体落点随 v0b 微信设计定；以后可加微信内切换命令。
