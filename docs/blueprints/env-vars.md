# B2：设置里的环境变量

状态：已批准（2026-10-30），实现中。

## 目的

skill 和脚本常要 token（如钉钉）。现在只能写进文件或对话，模型还会去 `env | grep` 探查。改为在设置里配好，命令直接用 `$NAME`；值始终脱敏，防止模型意外读到。逐字符打印、编码后输出这类有意绕过不在范围内，靠模型自觉。

## 行为

- **设置页**新增「环境变量」一节：增、删、改名字和值。值只写不读，页面只显示「已设置」，改值时重新输入。
  - 名字须是合法的 shell 变量名（`[A-Za-z_][A-Za-z0-9_]*`），不能和进程已有的变量重名，比如 `PATH`、`HOME`。
  - 值不少于 8 个字符，否则保存失败，提示「这里只放密钥类的值，至少 8 个字符」。普通配置写进 skill 或命令里。
- **生效**：`bash` 前台和后台命令都带上这些变量，子 agent 也一样。改完对下一条命令生效，已在运行的命令不受影响。
- **脱敏**：每个值登记进精确匹配名单，与主密钥、服务商 API key 同一套，出站请求里出现原值就换成 `<NAME>`。不受会话「凭据脱敏」开关影响，始终开启。
- **系统提示**：列出已设置的变量名，不带值，例如「Environment variables set for commands: `$DINGTALK_TOKEN`」。模型据此直接引用，不必探查。
- **备份与导入**：和服务商 API key 一样加密导出；导入时同名覆盖。

## 契约

- **mic-store**：新表 `core_env_vars(name TEXT PRIMARY KEY, value BLOB)`，值用主密钥加密（AAD 用名字）；schema 版本加一。提供读取全部名字与明文、写入、删除三个方法。
- **mic-tool**：`ToolContext` 增加只读的环境变量表，由 core 每次执行工具时从当前设置取得；`mic-tool-shell` 启动进程时注入。
- **mic-core**：`Redactor` 的精确名单改为运行期可更新，设置变化后替换；系统提示的 Environment 部分加上变量名一行。
- **mic-gateway**：`GET /settings/env`（只返回名字）、`PUT /settings/env/{name}`、`DELETE /settings/env/{name}`；校验失败返回中文原因。
- **Web**：设置页新增一节，样式复用服务商 API key 的输入。功能地图里设置一行补上「环境变量」。

## 验收

- **自动**：设置一个变量后跑 `bash` 打印它，送给模型的请求里只看到 `<NAME>`；值太短或名字非法时保存失败。
- **人工**：配好钉钉 token，让模型用 skill 列出表格，命令里直接用 `$NAME`，不再去 `env` 里找。
