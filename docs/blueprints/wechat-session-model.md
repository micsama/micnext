# B2：Web 切换微信会话模型

**状态：已批准并实现（2026-10-12）；本地 HTTP 验收通过，待 human 验收聊天页观感与真实微信。**

## 一、范围与用户行为

模型是会话属性，Web 只有一处设置入口：聊天页的模型选择器。本次让只读的渠道会话（现为微信）在聊天页也显示该选择器，与 Web 会话同一套交互；不另建微信模型配置，也不在「设置 → 微信」放第二个入口。

- 只读会话聊天页底部原有提示处显示模型选择器，并提示消息须在该渠道发送；人设选择本次不开放。
- 选择、默认显示、已删除提示、无模型提示沿用 Web 会话现有行为；切换只影响后续轮次，不改历史与上下文。
- 会话模型与人设规则一致：执行中也可切换，本轮不变，提示「已切换，下一轮生效」；执行中补发而并入本轮的输入仍用旧模型。取消原执行中 409（2026-10-12 human 决定），同步修订 [model-settings](model-settings.md)。
- 改全局默认不覆盖已有会话选择；同号重新登录沿用原会话及其选择；换号登录产生新会话，取当时默认。
- 「设置 → 微信」已绑定时提供「打开微信会话」跳转，模型在会话里改。

`/model` 后续另定，本次不新增斜杠命令。

## 二、公开契约与调用方影响

拆开两股语义：`writable` 只表示能否从 Web 发消息（仅 Web 会话）；会话模型属于会话设置，所有 Root 会话可改。

修订 `PUT /sessions/{id}/model`：Root 会话（任意渠道）均可调用，非 Root 会话返回 ReadOnly。请求仍为 `{ "model_id": number }`，成功 204；执行中不再返回 409（删除 `ModelSettingsError::SessionExecuting`）；不存在、模型已删除沿用现有规则。发消息、人设设置、上下文接口的权限不变。

无需扩展 DTO、core/store 公开签名或数据库结构，无新增依赖。

前端：`ChatView.svelte` 只读分支复用现有模型选择逻辑与提示，执行中不再禁用模型选择器（`ModelPicker` 去掉 `disabled`）；`WechatSection.svelte` 增加到绑定会话的跳转。
