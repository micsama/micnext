# B1：开发者日志留痕

**状态：已收敛（2026-10-12），见 [B2](../blueprints/developer-log-history.md)。**

## 一、需求

重启（手动或自动更新）后，网页仍能看到此前最近一段日志，用于排障。网页加快捷范围「全部 / 本次启动以来」。不做归档、压缩、全历史浏览。

现状：`crates/mic-gateway/src/logs.rs` 只有内存缓冲（10,000 条 / 16 MiB），进程退出即丢。原 [开发者诊断 B2](../blueprints/developer-diagnostics.md) 约定「内存日志、重启清空」，本次改契约，走 B2。

## 二、human 决定

| 问题 | 决定 |
|---|---|
| 历史范围 | 网页只看最近一段；旧日志不压缩、不归档，超限直接淘汰 |
| 「本次启动」分界 | 按进程：采集安装时生成 `boot_id`，手动重启和自动更新 exec 都会换新 |
| 持久化失败 | 降级，不停服 |
| 磁盘上限 | 日志目录总计 ≤ 100 MB |
| 落盘内容 | 只留排障所需，不必完整；隐私不额外设防，自用工具 |
| 存储 | 新鲜日志进 SQLite（独立库，限制大小）；SQLite 不可用则降级写纯文本 log 文件 |

上一轮的分段 JSONL、gzip/tar.gz、压缩任务、跨归档游标、队列溢出停服等方案全部作废。

## 三、草案

- **位置**：`<data_dir>/logs/`，内含 `logs.db`（独立于业务库 `micnext.db`）和降级文件 `micnext.log`。
- **落盘范围**：INFO 及以上；单条落盘文本另设较小上限（如 2 KiB，入 `limits.rs`）。DEBUG 和完整长字段只留在内存窗口供实时查看。
- **写入**：`DeveloperLogs` 在采集时把记录投进有界队列，由一条后台线程批量写入 SQLite。队列满就丢弃并计数，下一批补写一条「丢弃 N 条」记录，不阻塞 tracing。
- **早期记录**：采集先于数据目录解析安装。写入线程启动时先把内存缓冲中已有的本次记录补进库，然后接收新记录。
- **大小控制**：库超过上限（如 80 MB）时按 id 删最旧的一批，配合 `auto_vacuum = INCREMENTAL` 回收空间。降级文件写满上限（如 16 MB）后截断重写。两者合计不超过 100 MB。
- **降级**：打开或写入 SQLite 失败，本进程内改写 `micnext.log`，不再重试 SQLite；ERROR 记一条原因，网页日志页显示「日志库不可用，已改写到 <路径>」。降级文件也写失败则只剩内存，同样在页面提示。
- **收尾**：main 在 `stopped` 之后、exec 之前调用一次同步 flush，等待写入线程把队列写完。不为此延长数据目录锁的持有时间。
- **网页**：本次启动的记录仍走内存窗口和现有 SSE，不改。打开页面时额外一次性取库里的「之前启动」最近若干条（如 2,000 条，`boot_id != 当前`），拼在前面，不翻页。「本次启动以来」只显示内存部分。搜索、级别过滤照旧作用于已加载记录。
- **`-p`**：不打开日志库，行为不变。

## 四、B2 需要定的契约

1. `DeveloperLogs` 新增持久化入口和 flush（签名、错误类型）；main 获取数据目录的方式（预计 `Assembly::data_dir()` 公开 getter）。
2. `mic-gateway` 新增 `rusqlite` 直接依赖（与 `mic-store` 同版本），`logs.db` 的表结构和版本号；遇到未知版本时删库重建（日志可丢）。
3. 新增 HTTP 接口「之前启动的最近日志」的路径和返回形状，以及降级状态怎么告诉页面。
4. 列出现有日志里打印过长内容的 emit 点，在 emit 侧收短（「有些不必完整打印」）。

## 五、验收

手动重启、一键更新后，页面能看到上一次启动的日志；「本次启动以来」只剩本进程记录。连续运行到超过上限，日志目录不超过 100 MB。删掉或锁住 `logs.db` 后，服务继续运行，页面提示降级，`micnext.log` 有内容。`-p` 不产生日志文件。
