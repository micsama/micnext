# B1：聊天页后台任务呈现

状态：选定 A，已实现并验收（2026-10-19，随 async-jobs 关闭）。只改前端组件，接口不变，未出 B2。

## 现状与问题

- 后台任务是右侧 `w-80` 常驻侧栏：宽屏默认打开，挤占聊天栏；窄屏是覆盖层。只要会话有过任务就能打开，任务全部结束后侧栏仍在。
- 入口有两个：标题栏的任务按钮，以及消息流里工具行的「后台执行中」和「后台任务完成」。侧栏和消息流各说各的，两者之间没有关联。
- 侧栏每行信息量大：状态、类型、耗时、尾部三行输出、展开按钮、Trace、终止。多数时候用户只关心有没有任务在跑、跑完没有。

根因：后台任务是会话当下的状态，不是一个需要常驻的工作区，却按工作区的规格做成了侧栏。

## 候选

**A. 输入框上方的任务条（推荐）**
- 收起时是贴在 Composer 上沿的一条细栏：`⟳ 2 个任务运行中 · 1 个已完成`，每个任务一个小状态点，悬停看说明。
- 点开后在原位向上展开为卡片，盖住消息流底部，最高约 40vh，可滚动：每个任务一行（状态、说明、耗时，以及 Trace / 终止按钮）。点某一行，输出在行内展开。
- 何时整条显示：有运行中的任务，或有结束后还没看过的任务。全部看过后，同一个元素缩成输入框左上角的灰色小标签「N 个后台任务」，点开仍是同一张卡片，历史任务也从这里看。入口始终在原位，只改变轻重（human 2026-10-19：标题栏离输入框太远）。
- 优点：位置贴着输入框，追问、终止就在手边；不占横向空间，宽屏和窄屏同一种形态。
- 代价：输出很长时卡片里阅读偏挤，所以长输出加一个「全屏查看」，打开对话框。

**B. 标题栏弹出层**
- 去掉侧栏，只保留标题栏的任务按钮，点开是 Popover 列表。
- 最轻；但运行状态只能靠按钮上的小角标感知，读输出要在弹层里滚动。

**C. 并进消息流**
- 派发处的工具行改成实时卡片（状态、尾部输出、终止），「后台任务完成」并进同一张卡片，不再另起一条。
- 信息只有一处，最贴上下文；但卡片会随消息滚出视野，多个任务也没有汇总视图。agent 任务可以多次追问，跨越多个时间点，挂在哪条消息下并不自然。

## 建议

选 A，并吸收 C 的关联：消息流里派发和完成两行显示任务号，点任务号就展开任务条并定位到该任务，把两处串起来，任务的状态细节只在任务条里写。

只改前端，不动接口：沿用 `view.jobs`、`jobOutput`、`stopJob`。选定后先做一个原型供 check，再出 B2。
