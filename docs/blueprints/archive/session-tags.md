# B2：会话标签（受控词表）

**状态：CLOSED（human 2026-10-26 验收通过）。** 已批准（human 2026-10-26，标签名上限定为 4 字）。

依据：[B1 §3](../../brainstorm/session-sidebar.md#3-标签)。human 2026-10-23 已定：选 B 受控词表；标签随标题在同一次调用里生成，模型输出两行，不用 JSON。

## 行为

- **词表**：在设置里新增「标签」分组，可以新增、改名、删除标签。名字去掉首尾空白后不能为空，不超过 `TAG_CHARS`（4）字，不能含分隔符（`、` `,` `，` 和空白），也不能和已有标签重名。改名后，已经打上的会话跟着变。删除前确认，确认框写出有多少会话正在用这个标签；删除后这些会话上的这个标签也一并去掉。
- **打标签**：每个 Root 会话最多 `TAGS_PER_SESSION`（2）个标签。
  - 自动：第一次自动生成标题、以及手动点「重新生成标题」时，模型同时从词表里挑标签。
  - 手动：会话页标题旁显示当前标签，点开后可以勾选词表里的标签。手动改过一次以后，这个会话就不再自动打标签，重新生成标题也只改标题。
  - 词表为空，或者会话的标签是手动定的：调用和现在完全一样，只生成标题。
- **筛选**：词表不为空时，聊天侧栏顶部「新会话」下方出现一排单选标签「全部 · 工作 · 学习 …」，太多时横向滚动。选中某个标签后，置顶、日期分组和其它渠道都只列带这个标签的会话。选中状态只在当前页面内有效，刷新后回到「全部」。
- **行内展示**（改 B1 的「标签不进行」）：运行态改成边框跑马灯后，行尾不再放任何指示，标签放在标题右边、「⋯」左边：

  ```
  📌 帮我看下 nginx 配置为什么 502…  [代码][工作]  ⋯
     周报整理                            [工作]  ⋯
     Rust 生命周期问题                            ⋯
  ```

  - 小号淡色胶囊，最多 2 个；每块最多 4 字，两块合计不到行宽的三分之一。颜色按标签 id 从一组淡色里轮取，同一标签在筛选条、行内、会话页处处同色。
  - 行宽不够时先截断标题，标签不截断。
  - 正在筛选某个标签时，行内不再重复显示这个标签。

## 标题调用的输出格式

词表不为空、并且这个会话不是手动标签时，任务说明末尾附上词表，要求模型：

- 第一行输出标题，规则不变（非空，不超过 `TITLE_CHARS` 字）；
- 第二行输出标签，从词表里选 0–2 个，用「、」分隔；没有合适的就只输出一行，或者第二行留空。

解析规则：第二行接受 `、` `,` `，` 和空白作分隔，按名字精确匹配词表并去重。只要出现词表外的名字、超过 2 个、或者多于两行，整次调用按格式错误处理：标题和标签都不改，错误写进 `title_error`，和现在标题失败的提示一样，由用户点重试。

标题和标签在 `save_title_result` 的同一事务里写入。写入前再读一次会话的手动标记：如果生成期间用户已经手动改过标签，这次只写标题，不覆盖标签。

Trace 重建标题调用的输入时，词表按**当前**词表重建。这和普通调用重建系统提示词的做法一致，不另外保存当时的词表。

## 存储

```sql
CREATE TABLE core_tags (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,
  created_at INTEGER NOT NULL
);
CREATE TABLE core_session_tags (
  session_id INTEGER NOT NULL REFERENCES core_sessions(id),
  tag_id INTEGER NOT NULL REFERENCES core_tags(id) ON DELETE CASCADE,
  PRIMARY KEY (session_id, tag_id)
);
ALTER TABLE core_sessions ADD COLUMN tags_manual INTEGER NOT NULL DEFAULT 0;
```

- 颜色不入库：前端按 id 轮取淡色，B1 里的 `color` 列不需要。
- 手动标记是整个会话的属性，不是每个标签各自一份，所以放在 `core_sessions` 上。
- 侧栏按 id 顺序展示词表，不做拖拽排序。
- 备份导出与导入包含词表名字；导入只补上缺少的名字，已有标签不动。会话本身不进备份，所以会话和标签的对应关系也不进。
- 转换脚本按 `database-conversion` 的流程由 build.sh 执行，只建表、加列。

## HTTP 契约

| 接口 | 说明 |
|---|---|
| `GET /tags` | 返回 `[{ id, name, sessions }]`，按 id 升序；`sessions` 是正在用它的会话数，供删除确认 |
| `POST /tags` `{ name }` | 新增，返回 `{ id }`；名字不合法返回 400、重名返回 409，均带中文原因 |
| `PUT /tags/{id}` `{ name }` | 改名，校验同上 |
| `DELETE /tags/{id}` | 删除，同时去掉所有会话上的这个标签 |
| `PUT /sessions/{id}/tags` `{ tag_ids }` | 手动设置标签，同时置上手动标记；只允许没有归档的 Root 会话，最多 2 个，id 必须存在 |
| `GET /sessions?tag=`、`GET /sessions/pinned?tag=` | 可选参数，只返回带这个标签的会话；标签不存在时返回空列表 |

- `SessionItem` 新增 `tag_ids: number[]`。前端用 `GET /tags` 得到的词表把 id 映射成名字，名字只在词表这一处保存。
- 会话的标签变化后发 `session_changed`，复用现有的「收到事件后重拉」路径。
- 词表的变化不另发事件：侧栏在同步会话列表时一并重拉 `/tags`，设置页每次修改后也重拉。
- 删除一个标签时，如果侧栏正筛选着它，就回到「全部」。

## 调用方影响

- `mic-store`：
  - 新增标签的增删改查和会话打标签。
  - 两个列表查询接受可选的标签参数。
  - `SessionSummary` 带上 `tag_ids`。
  - `save_title_result` 的结果从 `Result<String, String>` 改为 `Result<TitleOutput, String>`，其中 `TitleOutput { title, tags: Option<Vec<TagId>> }`；`None` 表示不动标签。
  - 备份带上词表。
- `mic-core`：
  - `title_messages` 和 `parse_title` 增加词表。
  - 提交生成任务时读一次词表和会话的手动标记，决定这次要不要让模型挑标签；trace 重建也走同一路径。
  - 限制常量 `TAG_CHARS`、`TAGS_PER_SESSION` 放在 `mic-store` 的 `limits.rs`，store 写入与 core 解析共用。
- `mic-gateway`：新增上表里的路由，列表接口接受 `tag` 参数。
- Web：
  - 设置页新增「标签」分组。
  - 侧栏增加筛选条。
  - 会话页 Header 标题旁显示标签，点开是可勾选的弹出框，复用侧栏「⋯」的 Popover 样式；没有标签时显示「+ 标签」，归档会话只读，定时任务会话不显示。
  - `types.ts` 和 `client.ts` 同步更新。
- 微信等其它渠道的 Root 会话同样会生成标签，只在 Web 上看得到、能筛选。

## 验收

- store 测试：
  - 删除标签时，会话上的对应关系一并删掉；
  - 手动标记置上后，生成结果不覆盖标签；
  - 列表按标签过滤时，分页游标照常工作。
- core 测试：解析两行输出，包括正常、只有一行、词表外的名字、超过 2 个、多于两行。
- 人工验收：
  1. 建三个标签后发起新会话，确认自动打上标签。
  2. 手动改掉标签后点「重新生成标题」，确认只有标题变了。
  3. 在侧栏筛选，置顶和日期分组都只剩带这个标签的会话。
  4. 删除正在筛选的标签，侧栏回到「全部」。
